## 1. 交付目标摘要

本月聚焦 VPIphotonics 的 VPItoolkit PDK <fab> 体系对齐。VPIphotonics 提供 HHI/LIGENTEC/LioniX/SMART/Infinera/GPIC 六大 foundry 的 PDK 工具包，每个 PDK 包含 foundry 认证的 building block（BB）库，每个 BB 用 few user-defined 参数化，并关联 adequate simulation model。本月交付目标：(1) 对齐 VPItoolkit PDK 架构，新增 `src/polaris/pdk/vpi_style/` 模块；(2) 实现 ≥3 个 VPI 风格 foundry 模型库（HHI/LIGENTEC/LioniX）；(3) 系统级模型与电路级模型互操作；(4) 支持 PDAflow API 标准的 BB 交换；(5) 综合得分从 7.65 提升至 7.75。

## 3. 公式与理论依据

### 3.1 BB 参数化模型

VPI 风格 BB 用 few user-defined 参数化，模型函数为：

$$
\mathbf{S}_{BB}(\lambda; \mathbf{p}) = \mathbf{f}(\lambda, \mathbf{p}), \quad \mathbf{p} = [p_1, p_2, \dots, p_K]
$$

**变量定义**：
- $\lambda$：波长（μm）
- $\mathbf{p}$：用户参数向量（如长度、宽度、耦合系数）
- $\mathbf{f}$：紧凑模型函数（解析/查表/拟合）
- $K$：参数个数，通常 $K \le 5$（VPI 设计原则）

**推导来源**：Augustin 2018 JSTQE §IV-B；Melati 2012 JLT。

**适用条件**：BB 在 foundry 工艺窗口内，参数在认证范围内有效。

**数值示例**：SMART Photonics InP 波导 BB，$\mathbf{p} = [L, w]$，$L \in [0, 10^4]\ \mu m$，$w = 1.5\ \mu m$（固定），$S_{21} = e^{-\alpha L/2} e^{j\beta L}$。

### 3.2 BB 紧凑模型拟合

从 FDTD/测量 S 参数数据拟合 BB 紧凑模型：

$$
\min_{\mathbf{p}} \sum_{i} \left| S_{measured}(\lambda_i) - \mathbf{f}(\lambda_i, \mathbf{p}) \right|^2
$$

**变量定义**：
- $S_{measured}(\lambda_i)$：第 $i$ 个波长点的测量/FDTD S 参数
- $\mathbf{f}(\lambda_i, \mathbf{p})$：紧凑模型预测值
- 拟合方法：最小二乘 / Levenberg-Marquardt / RL（创新点）

**推导来源**：Melloni 2015 SPIE 96641L；Levenberg 1944。

**适用条件**：模型结构 $\mathbf{f}$ 已知，参数 $\mathbf{p}$ 可辨识。

### 3.3 PDAflow BB 交换格式

PDAflow API 定义 BB 的标准交换格式：

$$
BB = \{name, ports, params, model\_func, layout\_func, sources\}
$$

**变量定义**：
- `name`：BB 唯一标识（如 `"wg_strip_220nm"`）
- `ports`：端口列表（name, x, y, direction, width）
- `params`：参数定义（name, type, range, default）
- `model_func`：S 参数模型函数
- `layout_func`：GDS 生成函数
- `sources`：溯源 URL 列表

**推导来源**：PDAflow API 标准 http://pdaflow.org/。

**适用条件**：PDAflow 兼容工具间交换。

### 3.4 Foundry 工艺窗口约束

BB 参数需在 foundry 认证的工艺窗口内：

$$
\mathbf{p}_{min} \le \mathbf{p} \le \mathbf{p}_{max}, \quad \forall \mathbf{p} \in \mathcal{P}_{certified}
$$

**变量定义**：
- $\mathcal{P}_{certified}$：foundry 认证参数空间
- $\mathbf{p}_{min}, \mathbf{p}_{max}$：参数上下界

**推导来源**：Augustin 2018 JSTQE §IV-C。

**适用条件**：BB 模型仅在认证窗口内有效，超出需重新认证。

## 4. 开源方案缺点分析

### 4.1 gdsfactory PDK 桥接无系统级模型

- **问题描述**：gdsfactory 桥接 43+ PDK，但仅覆盖 layout（GDS 生成），无系统级 S 参数模型
- **影响**：用户需自行编写 S 参数模型，无法直接用于系统级仿真
- **来源 URL**: https://gdsfactory.github.io/gdsfactory/notebooks/08_pdk.html（无 system-level model）
- **根因分析**：gdsfactory 定位为版图工具，系统级模型依赖 SAX/Simphony 独立集成

### 4.2 SiEPIC PDK 仅覆盖 EBeam 单一平台

- **问题描述**：SiEPIC 开源 PDK 仅覆盖 UBC EBeam 220nm SOI 平台，无 InP/SiN/LNOI
- **影响**：无法支持多平台 foundry 设计
- **来源 URL**: https://github.com/SiEPIC/SiEPIC_EBeam_PDK
- **根因分析**：SiEPIC 为学术 PDK，商业 foundry PDK 需 NDA

### 4.3 Luceda IPKISS PDK 商业闭源

- **问题描述**：IPKISS 的 foundry PDK（AIM/AMF/CompoundTek/IHP）需商业授权，开源用户无法访问
- **影响**：开源用户无法使用 foundry 认证 BB
- **来源 URL**: https://www.lucedaphotonics.com/products/ipkiss（商业授权）
- **根因分析**：foundry PDK 含 NDA 信息，无法开源

### 4.4 OpenROAD-photonics 无 PDK 抽象层

- **问题描述**：OpenROAD 无光子 PDK 抽象层，仅支持电子 PDK（SkyWater130/GF180）
- **影响**：无法在 OpenROAD 流程中使用光子 BB
- **来源 URL**: https://github.com/The-OpenROAD-Project/OpenROAD
- **根因分析**：OpenROAD 聚焦电子 IC，光子扩展未实现 PDK 层

## 5. 源代码解读分析

### 5.1 `src/polaris/pdk/catalog.py` — DeviceCatalog

**关键函数**：
- `DeviceCatalog`：器件注册表，按平台/类别检索
- `build_default_catalog()`：构建默认器件库（SOI/SiN/InP/LNOI 四平台）

**当前实现逻辑**：
1. 字典注册 + 按名检索（参考 gdsfactory Pdk）
2. JSON/YAML 序列化
3. 81 个器件，全部溯源

**局限性**：
- 无 VPI 风格的 BB 抽象（model_func + layout_func + sources 一体化）
- 无 PDAflow API 兼容交换格式
- 无 foundry 认证参数窗口

**改进点**：
- 增加 `BuildingBlock` 类（VPI 风格），封装 model_func + layout_func + sources
- 增加 `PDAflowExporter` 类，支持 PDAflow 格式导出
- 增加 foundry 认证参数窗口标注

### 5.2 `src/polaris/pdk/foundry_platforms.py` — FoundryPlatform

**关键函数**：
- `FoundryPlatform` dataclass：foundry 平台元数据（name, process_node, waveguide_width_um 等）
- `FOUNDRY_PLATFORMS`：11 个公开 foundry 平台元数据

**当前实现逻辑**：
1. 公开参数（非 NDA），来自公开文献
2. 11 个 foundry（AIM/AMF/CompoundTek/IHP/GF/Tower/LIGENTEC/LioniX/VTT/Tyndall/HyperLight）

**局限性**：
- 仅元数据，无 BB 模型
- 无 VPI 风格的 PDK 工具包（VPItoolkit PDK <fab>）

**改进点**：
- 增加 `VPIToolkitPDK` 类，封装 foundry BB 库
- 实现 HHI/LIGENTEC/LioniX 三个公开 PDK 的 BB 库

### 5.3 `src/polaris/pdk/device.py` — Device

**关键函数**：
- `Device` dataclass：器件定义（name, ports, bbox, params, sources）
- `BoundingBox`：器件包围盒

**当前实现逻辑**：
1. 器件 = 端口 + 几何 + 参数 + 溯源
2. 无 S 参数模型函数（在 device_models.py 单独映射）

**局限性**：
- Device 与 S 参数模型分离，未一体化（VPI 风格 BB = Device + model_func + layout_func）
- 无 foundry 认证标注

**改进点**：
- 增加 `BuildingBlock(Device)` 子类，新增 `model_func`、`layout_func`、`certified_range` 字段

### 5.4 `src/polaris/sim/device_models.py` — 器件到 S 参数模型映射

**关键函数**：
- `_SMODEL_DISPATCH`：分发表，按器件名匹配 S 参数模型
- `_matches_waveguide(name)` / `_matches_ring(name)` 等：匹配函数

**当前实现逻辑**：
1. dispatch table 模式，降低圈复杂度
2. 51 器件到 S 参数模型映射

**局限性**：
- 模型与器件分离，无 VPI 风格的 BB 一体化
- 无 foundry 认证参数窗口

**改进点**：
- 将模型函数嵌入 `BuildingBlock` 类，实现 BB 一体化
- 增加 foundry 认证参数窗口检查

### 6.2 改进点

1. **BB 一体化**：将 Device + model_func + layout_func + certified_range 整合为 `BuildingBlock` 类，对齐 VPI 风格。
2. **PDAflow 兼容**：实现 PDAflow API 标准的 BB 交换，支持 VPI/IPKISS/OptoDesigner 互操作。
3. **Foundry PDK 库**：实现 HHI（InP）/LIGENTEC（SiN）/LioniX（TriPleX SiN）三个公开 PDK 的 BB 库。

### 6.3 创新点（标注"创新"）

1. **【创新】AI 驱动的 BB 紧凑模型自动拟合**：利用 PoLaRIS PPO 框架，从 FDTD/测量 S 参数数据自动拟合 BB 紧凑模型参数，替代 VPI 的人工参数提取。
   - *创新逻辑*：VPI 的 BB 模型参数依赖人工拟合（Levenberg-Marquardt），PoLaRIS 用 RL agent 探索参数空间，适用于非凸、多模态拟合。
   - *支持理论*：RL 优化黑盒函数（Sutton & Barto 2018 §13）；紧凑模型拟合为非凸问题。
   - *案例预估*：MMI 2x2 紧凑模型拟合，人工需 4 小时，RL agent 预计 15 分钟达到同等精度。

2. **【创新】BB 模型版本化与溯源**：每个 BB 模型关联 git commit + 数据源 URL + 推导公式 + 验证状态，支持模型可追溯。
   - *创新逻辑*：VPI 的 BB 模型为黑盒（foundry 提供），PoLaRIS 用 `ModelCard` 记录来源、参数范围、验证状态。
   - *支持理论*：Model Cards for Model Reporting（Mitchell et al., FAT* 2019）。
   - *案例预估*：BB 模型变更可追溯，减少 50% 的模型版本混乱问题。

3. **【创新】跨 foundry BB 自动映射**：利用 GNN 学习不同 foundry BB 的等价性，自动映射 BB（如 SOI waveguide ↔ SiN waveguide）。
   - *创新逻辑*：VPI 需手动为每个 foundry 编写 BB，PoLaRIS 用 GNN 学习 BB 等价性，自动跨平台映射。
   - *支持理论*：GNN 图同构匹配（Kipf & Welling, ICLR 2017）；BB 等价性 = 端口拓扑 + S 参数相似度。
   - *案例预估*：SOI→SiN BB 映射，自动准确率预计 ≥80%，减少 70% 人工映射工作。
