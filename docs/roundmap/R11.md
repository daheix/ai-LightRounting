## 1. 交付目标摘要

本路标完成 PoLaRIS 版图参数化代码驱动（Code-as-Layout）能力的对齐与超越。在阶段 1 已实现基础参数化器件（`foundry_devices.py` 系列，含 SOI/SiN/InP/LNOI 四大平台器件）的基础上，本路标实现 gdsfactory `@gf.cell` 装饰器范式的 100% 复刻，包括：函数式 PCell 定义、自动缓存（cache）、参数校验（pydantic）、命名唯一性保证、info 元数据附加；实现 KLayout PCell（C++ `db::PCell` 与 Ruby `PCellDeclaration`）的桥接；新增 PoLaRIS 原生参数化变换矩阵引擎，支持仿射/投影/非线性变换；实现"代码即版图"工作流，用户用 Python 函数定义 PCell，PoLaRIS 自动生成 GDS + 元数据 + 仿真模型。预期 PCell 定义效率较手写 GDS 提升 10×，参数化器件数从 ~50 提升至 200+。

## 3. 公式与理论依据

### 3.1 参数化变换矩阵

PCell 参数化通过仿射变换矩阵实现：

$$
\begin{pmatrix} x' \\ y' \\ 1 \end{pmatrix} = \begin{pmatrix} a & b & t_x \\ c & d & t_y \\ 0 & 0 & 1 \end{pmatrix} \begin{pmatrix} x \\ y \\ 1 \end{pmatrix}
$$

**变量定义**：
- $(x, y)$：原始坐标
- $(x', y')$：变换后坐标
- $a, b, c, d$：线性变换（旋转/缩放/剪切）
- $t_x, t_y$：平移

**推导来源**：计算机图形学经典理论，Foley et al., "Computer Graphics: Principles and Practice", Addison-Wesley 2013。

**特例**：
- 旋转 $\theta$：$a = \cos\theta, b = -\sin\theta, c = \sin\theta, d = \cos\theta$
- 缩放 $s$：$a = d = s, b = c = 0$
- 平移 $(t_x, t_y)$：$a = d = 1, b = c = 0$

### 3.2 PCell 缓存命中条件

`@gf.cell` 装饰器用参数元组作为缓存键，命中条件：

$$
\text{hit}(f, \theta) \iff \exists (f, \theta') \in \text{Cache}, \theta' = \theta
$$

**变量定义**：
- $f$：PCell 函数
- $\theta$：参数元组
- $\text{Cache}$：缓存字典

**推导来源**：gdsfactory `@gf.cell` 装饰器实现（https://gdsfactory.github.io/gdsfactory/）。

### 3.3 参数校验（Pydantic）

PCell 参数用 pydantic 模型校验：

$$
\text{valid}(\theta) \iff \forall i, \theta_i \in \text{Domain}(\theta_i)
$$

**变量定义**：
- $\theta_i$：第 $i$ 个参数
- $\text{Domain}(\theta_i)$：参数域（如 `width > 0`, `radius >= 5`）

**推导来源**：pydantic 类型校验（https://docs.pydantic.dev/）。

### 3.4 命名唯一性

PCell 命名用函数名 + 参数哈希：

$$
\text{name}(f, \theta) = f.\text{\_\_name\_\_} + "\_" + \text{hash}(\theta)
$$

**变量定义**：
- $\text{hash}(\theta)$：参数元组的哈希值

**推导来源**：gdsfactory Component 命名规则。

### 3.5 层次化 PCell 组合

复杂 PCell 通过组合简单 PCell 构建：

$$
C_{\text{complex}} = \bigcup_{i=1}^{N} T_i(C_i)
$$

**变量定义**：
- $C_i$：第 $i$ 个子 PCell
- $T_i$：第 $i$ 个变换矩阵
- $C_{\text{complex}}$：组合后的复杂 PCell

**推导来源**：gdsfactory hierarchical assembly（Matres et al., CLEO 2026）。

### 3.6 非线性变换（创新）

支持非线性变换（如贝塞尔弯曲）：

$$
\mathbf{p}(t) = (1-t)^3 \mathbf{P}_0 + 3(1-t)^2 t \mathbf{P}_1 + 3(1-t) t^2 \mathbf{P}_2 + t^3 \mathbf{P}_3
$$

**变量定义**：
- $\mathbf{P}_0, \mathbf{P}_1, \mathbf{P}_2, \mathbf{P}_3$：贝塞尔控制点
- $t \in [0, 1]$：参数

**推导来源**：Bezier 曲线理论（Farin, "Curves and Surfaces for CAGD", Morgan Kaufmann 2002）。

## 4. 开源方案缺点分析

### 缺点 1：gdsfactory PCell 缓存内存泄漏

- **问题描述**: gdsfactory `@gf.cell` 装饰器用全局字典缓存 Component，长时间运行导致内存泄漏。
- **影响**: 大规模设计流程内存占用持续增长。
- **来源 URL**: https://gdsfactory.github.io/gdsfactory/changelog.html
- **根因分析**: 全局缓存无 LRU 淘汰策略，旧 Component 永不释放。GDSFactory+ 1.8.5 changelog 标注"Memory management - Workspaces no longer use excessive memory"，说明是长期痛点。

### 缺点 2：gdsfactory PCell 参数校验延迟

- **问题描述**: gdsfactory PCell 参数校验在运行时（runtime）进行，错误发现晚。
- **影响**: 参数错误在 PCell 实例化时才暴露，调试成本高。
- **来源 URL**: https://gdsfactory.github.io/gdsfactory7/notebooks/08_pdk.html
- **根因分析**: gdsfactory 用 pydantic `@validate_arguments` 装饰器，运行时校验。无静态类型检查（mypy）集成。

### 缺点 3：KLayout PCell Ruby DSL 学习曲线

- **问题描述**: KLayout PCell 用 Ruby `PCellDeclaration` 类定义，与 Python 生态脱节。
- **影响**: Python 用户难以使用 KLayout PCell。
- **来源 URL**: https://www.klayout.org/doc-qt5/manual/pcell.html
- **根因分析**: 与 DRC/LVS 相同，KLayout 历史选型 Ruby。

### 缺点 4：gdsfactory 无多视图 PCell

- **问题描述**: gdsfactory PCell 仅有 Layout 视图，无 Circuit/Netlist 视图协同。
- **影响**: PCell 的电路/网表信息需手动维护，与版图不同步。
- **来源 URL**: https://gdsfactory.github.io/gdsfactory/
- **根因分析**: gdsfactory 设计为 layout-first，circuit/netlist 信息通过 `get_netlist` 函数事后提取，非原生多视图。IPKISS 支持多视图但商业付费。

### 缺点 5：gdsfactory 无 AI 辅助 PCell 生成

- **问题描述**: PCell 需手动编写 Python 函数，无 AI 辅助生成。
- **影响**: 新 PCell 开发耗时。
- **来源 URL**: https://gdsfactory.github.io/gdsfactory/
- **根因分析**: gdsfactory 无 LLM 集成。PhIDO（arXiv:2508.14123）验证 LLM 可配置 PCell 参数，但未生成 PCell 代码。

## 5. 源代码解读分析

### 5.1 文件：`/workspace/src/polaris/pdk/foundry_devices.py` 系列

**关键内容**：
- `foundry_devices.py`：基础 foundry 器件定义。
- `foundry_devices_active.py`：有源器件（激光器/调制器/探测器）。
- `foundry_devices_advanced.py`：高级器件（AWG/MTM 等）。
- `foundry_platforms.py`：foundry 平台元数据。

**当前实现逻辑**：
- 用 Python 函数定义器件，返回 `Device` 对象。
- 参数通过函数参数传入，无装饰器缓存。
- 器件数 ~50，远少于 gdsfactory 的数百个。

**局限性**：
1. **无 `@cell` 装饰器**：每次调用重新生成 Device，无缓存。
2. **无参数校验**：参数错误在运行时暴露。
3. **无多视图**：仅有 Layout 视图（Device 含 ports/bbox），无 Circuit/Netlist 视图。
4. **器件数少**：~50 个，远少于 gdsfactory 的数百个。
5. **无 AI 辅助**：PCell 需手动编写。

**改进点**：
- 新增 `@polaris_cell` 装饰器，实现缓存 + 参数校验 + 命名唯一性。
- 新增 `PCellMultiView` 类，支持 Layout/Circuit/Netlist 三视图。
- 扩展器件库至 200+，覆盖 gdsfactory 主要器件。
- 新增 `ai_generate_pcell(description)` 函数，用 LLM 生成 PCell 代码。

### 5.2 文件：`/workspace/src/polaris/pdk/device.py`

**关键内容**：
- `Device` dataclass：含 `device_id` / `platform` / `category` / `name` / `ports` / `bbox` / `params` / `process_node`。
- `BoundingBox` dataclass：xmin/ymin/xmax/ymax。
- `Port` 类：含 name/x/y/direction/waveguide_type/width。

**当前实现逻辑**：
- Device 为不可变 dataclass，ports 为列表。
- 无多视图支持。

### 5.3 文件：`/workspace/src/polaris/pdk/gdsfactory_integration.py`

已实现 `gdsfactory_to_polaris_device` 转换，但未实现反向转换（PoLaRIS Device → gdsfactory Component）。

### 6.3 改进点

1. **`@polaris_cell` 装饰器**：实现缓存（含 LRU 淘汰）+ 参数校验（pydantic）+ 命名唯一性。
2. **多视图 PCell**：实现 `PCellMultiView` 类，含 Layout/Circuit/Netlist 三视图。

### 6.4 创新点（标注"创新"）

1. **【创新】AI 辅助 PCell 代码生成**：用 LLM 从自然语言描述生成 PCell Python 代码。
   - **创新逻辑**：gdsfactory 无此能力（缺点 5），PhIDO 仅配置参数不生成代码。PoLaRIS 用 LLM 生成完整 PCell 函数。
   - **支持理论**：PhIDO（arXiv:2508.14123）验证 LLM 可理解光子电路结构；Code LLM（Codex/AlphaCode）可生成领域代码。
   - **案例**：输入"生成一个半径 5μm、间隙 200nm 的环谐振器 PCell"，LLM 输出完整 Python 函数（含 `@polaris_cell` 装饰器、参数校验、几何生成、端口定义）。

2. **【创新】多视图 PCell 同步**：PCell 的 Layout/Circuit/Netlist 三视图自动同步，修改一处自动更新其他视图。
   - **创新逻辑**：gdsfactory 无多视图（缺点 4），IPKISS 支持但商业付费。PoLaRIS 用观察者模式（Observer Pattern）实现自动同步。
   - **支持理论**：Observer Pattern（Gamma et al., "Design Patterns", Addison-Wesley 1994）。

3. **【创新】非线性变换引擎**：支持贝塞尔曲线/样条曲线等非线性变换，用于复杂弯曲波导生成。
   - **创新逻辑**：gdsfactory 仅支持仿射变换 + 欧拉弯曲，无通用非线性变换。PoLaRIS 用贝塞尔/样条实现任意曲率变化。
   - **支持理论**：Bezier 曲线理论（Farin 2002）；B-spline 理论（de Boor, "A Practical Guide to Splines", Springer 2001）。

## 7. 改进计划路线图

### 步骤 1（W1-W2）：`@polaris_cell` 装饰器

- **任务**：实现 `@polaris_cell` 装饰器，含缓存（LRU）、参数校验（pydantic）、命名唯一性。
- **依赖**：`pydantic`（已安装）、`functools.lru_cache`。
- **验收标准**：1000 次同参数调用，缓存命中率 >99%，内存稳定（LRU 淘汰）。
- **风险**：LRU 容量需调优，过小导致频繁重生成，过大导致内存膨胀。

### 步骤 2（W2-W3）：多视图 PCell

- **任务**：实现 `PCellMultiView` 类，含 Layout/Circuit/Netlist 三视图，用观察者模式同步。
- **依赖**：步骤 1 完成。
- **验收标准**：修改 Layout 视图后，Circuit/Netlist 视图自动更新。
- **风险**：观察者模式在复杂 PCell 上可能有性能开销。

### 步骤 3（W3）：参数化变换矩阵引擎

- **任务**：实现 `Transform` 类，含仿射/旋转/缩放/剪切/贝塞尔变换。
- **依赖**：`numpy`（矩阵运算）。
- **验收标准**：贝塞尔变换在 4 控制点上生成平滑曲线，误差 <0.1μm。
- **风险**：低风险，矩阵运算成熟。

### 步骤 4（W3-W4）：器件库扩展至 200+

- **任务**：扩展 foundry_devices 系列，新增 150+ 器件（MMI 阵列/DC 阵列/环阵列/AWG/MTM 等）。
- **依赖**：步骤 1 完成。
- **验收标准**：器件数 ≥200，每个器件含 `@polaris_cell` 装饰器 + 参数校验。
- **风险**：器件数多，需批量生成模板。

### 步骤 5（W4）：AI 辅助 PCell 生成 + KLayout 桥接（创新）

- **任务**：实现 `ai_generate_pcell(description)` 函数 + KLayout PCell 桥接。
- **依赖**：LLM API、`klayout.db` PCell API。
- **验收标准**：AI 生成的 PCell 代码可执行且 DRC clean；KLayout PCell 可在 PoLaRIS 中实例化。
- **风险**：LLM 输出代码质量不稳定，需 schema 校验 + 测试。
