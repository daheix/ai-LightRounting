## 1. 交付目标摘要

本路标完成 PoLaRIS 对 gdsfactory PDK 生态的深度桥接与超越。在阶段 1 已实现 gdsfactory 基础集成（`gdsfactory_to_polaris_device` / `load_gdsfactory_pdk` / `list_gdsfactory_pdks`）的基础上，本路标实现 gdsfactory 43+ PDK 生态的 100% 桥接，包括：ubcpdk / gf180mcu / ihp / skywater130 / openfasoc / vtt / aim / amf / ligentec / vsc 等主流 PDK；实现 gdsfactory `Component` / `CrossSection` / `LayerStack` / `Port` 四大核心抽象的完整转换；实现 gdsfactory YAML-based 布局生成（`.pic.yml`）的解析与执行；新增 PoLaRIS 原生 PDK 注册机制，支持用户自定义 PDK 注册与 gdsfactory PDK 互操作。预期 PDK 覆盖数从 9 个 foundry 提升至 43+ PDK，对齐 gdsfactory 的 PDK 生态规模。

## 3. 公式与理论依据

### 3.1 参数化几何变换

gdsfactory PCell 用参数化函数定义几何，参数通过函数参数传入：

$$
\text{Polygon}(\theta) = \{(x_i(\theta), y_i(\theta))\}_{i=1}^{N}
$$

**变量定义**：
- $\theta = (\theta_1, \theta_2, \ldots, \theta_k)$：参数向量（如 width, length, radius）
- $(x_i, y_i)$：多边形顶点坐标

**推导来源**：gdsfactory PCell 函数式编程模型（Matres et al., CLEO 2026）。

**数值示例**：taper PCell 参数 $\theta = (L, w_1, w_2)$，顶点 $(0, 0), (L, 0), (L, w_2/2), (0, w_1/2)$。

### 3.2 端口朝向转换

gdsfactory 用 `orientation`（度，0=东, 90=北, 180=西, 270=南），PoLaRIS 用 `Direction` 枚举：

$$
\text{Direction}(\theta) = \begin{cases}
\text{EAST} & \text{if } \theta \in [-45°, 45°) \\
\text{NORTH} & \text{if } \theta \in [45°, 135°) \\
\text{WEST} & \text{if } \theta \in [135°, 225°) \\
\text{SOUTH} & \text{if } \theta \in [225°, 315°)
\end{cases}
$$

**推导来源**：PoLaRIS `_orientation_to_direction` 函数（`/workspace/src/polaris/pdk/gdsfactory_integration.py` 第 253-256 行）。

### 3.3 PDK 注册表映射

PoLaRIS PDK 注册表为映射 $R: \text{PDK\_name} \to \text{FoundryRunset}$：

$$
R = \{(\text{"SiEPIC\_EBeam"}, R_{\text{SiEPIC}}), (\text{"AMF"}, R_{\text{AMF}}), \ldots\}
$$

gdsfactory PDK 注册表为映射 $G: \text{PDK\_name} \to \text{PDK}$，桥接函数 $B: G \to R$：

$$
B(g) = \text{FoundryRunset}(\text{foundry\_name}=g.\text{name}, \text{rules}=\text{convert}(g.\text{drc\_rules}))
$$

**推导来源**：PoLaRIS `load_gdsfactory_pdk` 函数（`/workspace/src/polaris/pdk/gdsfactory_integration.py` 第 464-498 行）。

### 3.4 Component 缓存命中率

gdsfactory `@gf.cell` 装饰器缓存 Component，缓存命中率：

$$
\eta_{\text{cache}} = \frac{N_{\text{hit}}}{N_{\text{hit}} + N_{\text{miss}}} \times 100\%
$$

**变量定义**：
- $N_{\text{hit}}$：缓存命中次数
- $N_{\text{miss}}$：缓存未命中次数

**推导来源**：gdsfactory `@gf.cell` 装饰器文档（https://gdsfactory.github.io/gdsfactory/）。

**数值示例**：1000 次 mmi1x2(width=0.5) 调用，首次 miss，后续 999 次 hit，$\eta_{\text{cache}} = 99.9\%$。

### 3.5 YAML 布局解析复杂度

gdsfactory `.pic.yml` 解析复杂度：

$$
T_{\text{parse}} = O(|Y| \cdot N_{\text{inst}})
$$

**变量定义**：
- $|Y|$：YAML 文件大小
- $N_{\text{inst}}$：实例数

**推导来源**：gdsfactory `from_yaml` 函数（https://github.com/gdsfactory/gdsfactory/blob/main/gdsfactory/read/from_yaml.py）。

## 4. 开源方案缺点分析

### 缺点 1：gdsfactory `get_component` 异常难诊断

- **问题描述**: gdsfactory `get_component` 抛出 `ValueError` / `KeyError` / `TypeError` / `AttributeError` / `NotImplementedError` 等多种异常，新手难以定位。
- **影响**: 组件加载失败导致设计流程中断，调试耗时。
- **来源 URL**: https://blog.csdn.net/gitblog_07088/article/details/148823564
- **根因分析**: `get_component` 需处理多种输入类型（string/Component/ComponentFactory/dict）并与 PDK 紧密交互，异常高发。`ValueError` 占 65%。

### 缺点 2：gdsfactory 跨 PDK 组件名冲突

- **问题描述**: 不同 PDK 之间存在组件名冲突（如多个 PDK 都有 `mmi1x2`），基础 PDK 未正确继承或扩展，导致 `AttributeError: 'MyPDK' object has no attribute 'layer_stack'`。
- **影响**: 多 PDK 混用时报错，需手动隔离。
- **来源 URL**: https://blog.csdn.net/gitblog_07088/article/details/148823564
- **根因分析**: gdsfactory PDK 注册机制无命名空间隔离，组件名全局唯一性未强制。

### 缺点 3：gdsfactory 版本兼容性问题

- **问题描述**: gdsfactory 8.18.0 锁定 `pydantic<2.10`，而 `pydantic<2.10` 的 `pydantic-core` 无 Python 3.14 wheel，导致 Python 3.14 环境下 gdsfactory import 失败。
- **影响**: 新版 Python 用户无法使用 gdsfactory。
- **来源 URL**: https://gdsfactory.github.io/gdsfactory/changelog.html
- **根因分析**: gdsfactory 上游版本锁定策略保守，与 Python 新版本发布周期不匹配。

### 缺点 4：gdsfactory YAML 布局功能有限

- **问题描述**: gdsfactory `.pic.yml` 不支持复杂条件逻辑（如 if/else）、循环、变量计算，需用 Python 代码补充。
- **影响**: 纯 YAML 无法表达复杂设计，需混合 Python + YAML。
- **来源 URL**: https://deepwiki.com/gdsfactory/gdsfactory/5.2-yaml-based-layout-generation
- **根因分析**: YAML 是声明式语言，天然不支持过程化逻辑。gdsfactory 用 Jinja2 模板扩展（`${settings.var}`），但功能有限。

### 缺点 5：gdsfactory PDK 加载稳定性问题

- **问题描述**: GDSFactory+ 1.8.13 修复了"PDK 加载失败导致 app server 崩溃"问题，说明 PDK 加载稳定性是长期痛点。
- **影响**: PDK 加载失败中断整个设计流程。
- **来源 URL**: https://gdsfactory.com/plus/changelog/
- **根因分析**: PDK 加载涉及多模块导入、层映射、组件注册，任一环节失败均导致崩溃。1.8.13 修复为"跳过缺失 import/package 的条目"而非崩溃。

## 5. 源代码解读分析

### 5.1 文件：`/workspace/src/polaris/pdk/gdsfactory_integration.py`

**关键函数**：

- `is_available()`：检查 gdsfactory 是否可 import 且 PDK 可激活。
- `generate_mzi_gds(output_path, delta_length_um, bend_radius_um)`：用 ubcpdk 或 generic_pdk 生成 MZI GDS。
- `generate_ring_resonator_gds(output_path, radius_um, gap_nm)`：生成 Ring Resonator GDS。
- `generate_component_gds(component_name, output_path, **kwargs)`：通用 gdsfactory 器件 GDS 生成。
- `list_available_components()`：列出 gdsfactory 可用器件名。
- `gdsfactory_to_polaris_device(component, device_id, config)`：将 gdsfactory Component 转换为 PoLaRIS Device。
- `_extract_gdsfactory_ports(component)`：从 gdsfactory Component 提取端口列表。
- `_extract_gdsfactory_bbox(component)`：从 gdsfactory Component 提取包围盒。
- `list_gdsfactory_pdks()`：列出已安装的 gdsfactory PDK（generic/ubcpdk/gf180/ihp）。
- `load_gdsfactory_pdk(pdk_name, max_components)`：加载 gdsfactory PDK 器件为 PoLaRIS Device 字典。

**当前实现逻辑**：
- gdsfactory 为可选依赖（`try: import gdsfactory`），import 失败时 `_HAS_GDSFACTORY = False`。
- 端口朝向用 `_orientation_to_direction` 归一化到最近 90° 倍数。
- PDK 加载：激活 PDK → 遍历组件 → 转换为 Device → 返回字典。
- 平台映射：generic/ubcpdk → ("SOI", "220nm SOI")。

**局限性**：
1. **PDK 支持数少**：仅检测 generic/ubcpdk/gf180/ihp 共 4 个 PDK，未覆盖 gdsfactory 43+ PDK 生态。
2. **无 LayerStack 转换**：仅转换 Component/Port/BBox，未转换 LayerStack（层堆叠，含厚度/材料/z 位置）。
3. **无 CrossSection 转换**：未转换 gdsfactory CrossSection（截面定义，含多 Section）。
4. **无 YAML 布局解析**：未实现 `.pic.yml` 解析。
5. **无 PDK 注册机制**：PoLaRIS 无原生 PDK 注册 API，无法注册用户自定义 PDK。
6. **端口朝向损失**：非 90° 倍数的朝向（如 45°）被归一化到最近 90°，损失精度。

**改进点**：
- 扩展 PDK 检测列表至 43+ PDK（ubcpdk/gf180/ihp/skywater130/openfasoc/vtt/aim/amf/ligentec/vsc 等）。
- 新增 `convert_layerstack(gf_layerstack)` 函数，转换 LayerStack。
- 新增 `convert_crosssection(gf_xs)` 函数，转换 CrossSection。
- 新增 `parse_pic_yaml(yaml_path)` 函数，解析 `.pic.yml`。
- 新增 `register_polaris_pdk(name, pdk)` API，注册用户自定义 PDK。
- 端口朝向保留原始角度（float），不强制归一化。

### 5.2 文件：`/workspace/src/polaris/pdk/foundry_devices.py` 系列

PoLaRIS 现有 foundry_devices 模块（含 `_active` / `_advanced` 后缀）定义了 SOI/SiN/InP/LNOI 四大平台的器件库，但器件数远少于 gdsfactory 的数百个。

2. **LayerStack 转换**：转换 gdsfactory LayerStack（含厚度/材料/z 位置/折射率）为 PoLaRIS LayerStack。

### 6.4 创新点（标注"创新"）

1. **【创新】PDK 互操作层**：实现 PoLaRIS PDK ↔ gdsfactory PDK 双向转换，用户可在 PoLaRIS 中用 gdsfactory PDK 器件，也可在 gdsfactory 中用 PoLaRIS 自定义器件。
   - **创新逻辑**：gdsfactory 仅支持自身 PDK 生态，无双向互操作。PoLaRIS 提供 `polaris_to_gdsfactory_component` 反向转换函数。
   - **支持理论**：互操作层模式（Interoperability Layer Pattern），参见 Fowler, "Patterns of Enterprise Application Architecture", Addison-Wesley 2002。
   - **案例**：用户在 PoLaRIS 中定义自定义 LNOI 器件，通过 `polaris_to_gdsfactory_component` 转换为 gdsfactory Component，可在 gdsfactory 路由器中使用。

2. **【创新】PDK 自动版本兼容**：检测 gdsfactory 版本与 Python 版本，自动选择兼容的 PDK 加载策略（如 Python 3.14 下跳过 pydantic<2.10 锁定的 PDK）。
   - **创新逻辑**：gdsfactory 版本兼容性问题（缺点 3）需用户手动处理，PoLaRIS 自动检测并降级。
   - **支持理论**：语义化版本控制（SemVer，https://semver.org）。

3. **【创新】PDK 组件冲突检测**：在多 PDK 加载时，自动检测组件名冲突（如多个 PDK 都有 `mmi1x2`），生成冲突报告并建议命名空间隔离（如 `ubcpdk.mmi1x2` vs `gf180.mmi1x2`）。
   - **创新逻辑**：gdsfactory 缺点 2 的根因是组件名全局唯一性未强制，PoLaRIS 主动检测并隔离。
   - **支持理论**：命名空间隔离模式（Namespace Isolation Pattern）。

## 7. 改进计划路线图

### 步骤 1（W1-W2）：43+ PDK 桥接扩展

- **任务**：扩展 `list_gdsfactory_pdks` 与 `load_gdsfactory_pdk`，支持 ubcpdk/gf180/ihp/skywater130/openfasoc/vtt/aim/amf/ligentec/vsc 等 43+ PDK。
- **依赖**：gdsfactory 8.18.0+、各 PDK 包（ubcpdk/gf180mcu-pdk/IHP-Open-PDK 等）。
- **验收标准**：至少 20 个 PDK 可成功加载并转换为 PoLaRIS Device 字典。
- **风险**：部分 PDK 可能未安装，需 graceful degradation。

### 步骤 2（W2）：LayerStack 与 CrossSection 转换

- **任务**：实现 `convert_layerstack(gf_layerstack)` 与 `convert_crosssection(gf_xs)` 函数。
- **依赖**：gdsfactory LayerStack/CrossSection API。
- **验收标准**：ubcpdk LayerStack 转换后，层厚度/材料/z 位置 100% 一致。
- **风险**：gdsfactory LayerStack 结构复杂（含多层 LayerLevel），需逐层转换。

### 步骤 3（W3）：YAML 布局解析

- **任务**：实现 `parse_pic_yaml(yaml_path)` 函数，支持 instances/placements/connections/routes/ports 五大段。
- **依赖**：`pyyaml`、`pydantic`（schema 校验）。
- **验收标准**：gdsfactory 官方 yaml_pics 示例（如 `aar_simple.pic.yml`）解析成功。
