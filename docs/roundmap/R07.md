## 1. 交付目标摘要

本路标完成 PoLaRIS 对 KLayout DRC（Design Rule Checking）引擎的深度对齐与超越。在阶段 1 已实现 16 项基础 DRC 检查与 SiEPIC EBeam runset 的基础上，本路标扩展至 6 类核心 DRC 检查（width/space/notch/enclosed/area/density）的完整 KLayout Region API 复刻，新增 8 项 foundry-grade DRC 规则（含 density、enclosure、antenna、step coverage），引入层次化（hierarchical）DRC 模式以解决 KLayout 在大规模版图上的性能瓶颈（参考 KLayout Issue #2027 中 `width>` 检查挂起问题），并集成 OpenDRC 论文中的 layer-wise BVH（Bounding Volume Hierarchy）+ 自适应行分块算法。预期 DRC 检查速度较 KLayout flat 模式提升 5×，规则覆盖率达 KLayout Region API 的 100%。

## 3. 公式与理论依据

### 3.1 几何布尔运算

DRC 检查的基础是几何布尔运算（Boolean operations），定义于多边形集合上：

$$
A \oplus B = \{ p \mid p \in A \text{ or } p \in B \} \quad \text{(并集)}
$$

$$
A \otimes B = \{ p \mid p \in A \text{ and } p \in B \} \quad \text{(交集)}
$$

$$
A \ominus B = \{ p \mid p \in A \text{ and } p \notin B \} \quad \text{(差集)}
$$

**变量定义**：
- $A, B$：多边形集合（Region）
- $p$：二维平面上的点

**推导来源**：计算几何经典理论，参见 de Berg et al., "Computational Geometry: Algorithms and Applications", Springer 2008, Ch. 2（Line Segments Intersection）。

**适用条件**：多边形为简单多边形（simple polygon），边不自相交。

### 3.2 距离检查公式

**Width 检查**（同层图形内部最小宽度）：

$$
\text{Width}(P) = \min_{e_i, e_j \in \partial P, e_i \parallel e_j, \text{opposite}} d(e_i, e_j)
$$

其中 $d(e_i, e_j)$ 为两条平行对边之间的垂直距离，$\partial P$ 为多边形 $P$ 的边界。

**Space 检查**（同层不同图形最小间距）：

$$
\text{Space}(P_i, P_j) = \min_{p \in P_i, q \in P_j} \|p - q\|_2
$$

**推导来源**：KLayout Region API 文档（https://www.klayout.org/doc-qt5/manual/drc_runsets.html），OpenDRC 论文 Section IV-D。

**适用条件**：曼哈顿几何；非曼哈顿几何需用 PDRC 的层次化区间列表扩展。

### 3.3 层密度计算公式

CMP（Chemical-Mechanical Polishing）工艺要求各层密度在指定范围内，避免抛光不均匀：

$$
\rho = \frac{\sum_{i=1}^{N} A_i}{A_{\text{total}}} \times 100\%
$$

**变量定义**：
- $A_i$：第 $i$ 个图形的面积
- $A_{\text{total}}$：cell 总面积（通常为 bbox 面积）
- $\rho$：层密度百分比

**约束**：$\rho_{\min} \leq \rho \leq \rho_{\max}$，典型值 $\rho_{\min} = 30\%$，$\rho_{\max} = 70\%$。

**推导来源**：Banerjee, "CMOS Photonic Circuits", Springer 2024；SiEPIC EBeam PDK density rules。

**数值示例**：若 cell bbox 为 $100 \times 100 \, \mu\text{m}^2 = 10000 \, \mu\text{m}^2$，WG 层图形总面积 $3500 \, \mu\text{m}^2$，则 $\rho = 3500 / 10000 \times 100\% = 35\%$，在 [30%, 70%] 范围内，DRC clean。

### 3.4 层次化 BVH 查询复杂度

OpenDRC 提出的 layer-wise BVH 将层范围查询复杂度从 $O(n)$ 降至：

$$
T_{\text{query}} = O\left(\min(n, k \cdot h)\right)
$$

**变量定义**：
- $n$：叶节点数
- $k$：输出数
- $h$：层次树高度

**推导来源**：OpenDRC 论文 Section IV-A，基于 R-tree 经典理论（Guttman 1984）。

### 3.5 并行扫描线复杂度

X-Check 的并行垂直扫描线算法复杂度：

$$
T_{\text{parallel}} = O\left(\sqrt{n} \log n\right) \quad \text{depth}
$$

当 block 数 $b = \Theta(\sqrt{n})$ 时取得最优并行深度。

**推导来源**：X-Check 论文 Section "Complexity Analysis"，基于并行前缀和理论（Blelloch 1990）。

## 4. 开源方案缺点分析

### 缺点 1：KLayout `width>` 检查在大规模版图上挂起

- **问题描述**: KLayout 的 `layer.drc(width > value)` 检查在精细离散化多边形上极慢甚至挂起，而 `width < value` 检查正常。
- **影响**: 设计师无法对金属层执行最大宽度规则检查（max-width rule），需手动 snap 到粗网格降低顶点数，损失 DRC 精度。
- **来源 URL**: https://gitmemories.com/KLayout/klayout/issues/2027
- **根因分析**: KLayout 作者 Matthias 解释："width greater something" 不是距离检查，需更复杂分析（"report edges without an opposite one within a distance of 10um, unless edge pairs perpendicular to that are closer than 10um"），通用情况下复杂度高。建议用 negative sizing 替代，但需分步执行避免性能问题。

### 缺点 2：KLayout flat 模式大规模版图性能瓶颈

- **问题描述**: GF180 PDK 在中等规模版图（410k stdcells）上 DRC 运行 >10 小时，内存 >40GB。
- **影响**: 设计师无法在消费级硬件上运行完整 DRC，需高端服务器，阻碍开源 EDA 普及。
- **来源 URL**: https://wiki.f-si.org/images/1/19/FSiC2023_KLayout_DRCLVS_best_practices.pdf
- **根因分析**: flat 模式不利用层次化结构，中间结果堆积导致内存爆炸；GC（垃圾回收）被禁用的 bug 加剧问题。优化后（deep mode + 规则重写）降至 1h/<4G，但仍需手动调优。

### 缺点 3：KLayout Ruby API 学习曲线陡峭

- **问题描述**: KLayout DRC runset 使用 Ruby DSL（Domain-Specific Language），与主流 Python 生态脱节，新用户学习成本高。
- **影响**: 高校教学与企业采用受阻，社区贡献门槛高。
- **来源 URL**: https://www.klayout.org/doc-qt5/manual/drc_runsets.html
- **根因分析**: KLayout 历史选型 Ruby（2007 年），当时 Python 科学计算生态未成熟。虽有 `klayout.db` Python 绑定，但 DRC DSL 仍为 Ruby，Python 用户需切换心智模型。

### 缺点 4：KLayout 无 AI 辅助规则生成

- **问题描述**: DRC 规则需手动从 foundry design manual 翻译为 Ruby 脚本，耗时且易错。
- **影响**: 新 PDK 接入周期长（典型 2-4 周），规则遗漏导致 tape-out 失败。
- **来源 URL**: https://github.com/KLayout/klayout/issues（搜索 "DRC rule generation"）
- **根因分析**: KLayout 作为传统 EDA 工具，无 LLM/AI 集成。规则生成依赖工程师经验，无自动化路径。

### 缺点 5：KLayout deep mode 层次退化

- **问题描述**: KLayout deep mode 在某些操作（如 `interact`、pre-merge）下会破坏层次结构，导致结果传播至父 cell，性能退化至 flat 模式水平。
- **影响**: 复杂 DRC 规则（含 `interact`）在层次化版图上性能不可预测。
- **来源 URL**: https://wiki.f-si.org/images/1/19/FSiC2023_KLayout_DRCLVS_best_practices.pdf（"Deep Mode Best Practices" 章节）
- **根因分析**: deep mode 的 "visitor pattern" 在非局部操作（non-local operations）下需 pre-merge 形成大多边形，破坏层次结构。KLayout 作者标注为已知限制。

## 5. 源代码解读分析

### 5.1 文件：`/workspace/src/polaris/sim/klayout_drc.py`

**关键函数**：

- `KLayoutDRCRunner.run_gds(gds_path, runset)`：DRC 入口，加载 GDS → 遍历规则 → 调用 `_run_rule` 分发。
- `KLayoutDRCRunner._run_rule(layout, cell, rule, dbu)`：规则分发器，按 `DRCCheckType` 调用 `_check_width` / `_check_space` / `_check_notch` / `_check_enclose` / `_check_area` / `_check_density`。
- `KLayoutDRCRunner._check_width(region, rule, dbu)`：调用 `region.width_check(threshold_dbu)`，返回 edge_pairs 转 Violation。
- `KLayoutDRCRunner._check_density(region, rule, dbu, cell)`：计算 $\rho = \text{region.area()} / \text{cell.bbox().area()} \times 100\%$，检查是否在 [min, max] 范围。

**当前实现逻辑**：
- 直接封装 `klayout.db.Region` 的 `width_check` / `space_check` / `notch_check` / `enclosed_check` API。
- 支持 6 类 DRC 检查（WIDTH/SPACE/NOTCH/ENCLOSE/AREA/DENSITY）。
- SiEPIC EBeam 默认 runset 含 10 条规则（WG/DEEPTRENCH/SLAB150/GE/VIAC 层）。

**局限性**：
1. **无层次化模式**：当前为 flat 模式，未实现 deep/tiled 模式，大规模版图性能差。
2. **无 GPU 加速**：纯 CPU 单线程，未利用 OpenDRC/X-Check 的 GPU 并行算法。
3. **缺规则类型**：未实现 antenna、step coverage、density window（滑窗密度）等高级规则。
4. **无 AI 规则生成**：规则需手动编写，无 LLM 辅助。
5. **无 `width>` 检查**：未实现 KLayout Issue #2027 中提到的 max-width 检查（用 negative sizing 替代方案）。

**改进点**：
- 新增 `HierarchicalDRCRunner` 类，实现 layer-wise BVH + 自适应行分块。
- 新增 `GPUDRCRunner` 类（可选），集成 OpenDRC 的 CUDA kernel。
- 扩展 `DRCCheckType` 枚举：ANTENNA、STEP_COVERAGE、DENSITY_WINDOW。
- 新增 `max_width_check` 方法，用 negative sizing 实现 `width>` 检查。

### 5.2 文件：`/workspace/src/polaris/sim/foundry_runsets.py`

**关键内容**：
- `FoundryRunset` dataclass：封装 foundry 名、工艺节点、材料平台、规则列表、源 URL。
- `FOUNDRY_RUNSETS` 字典：注册 SiEPIC_EBeam / AMF / IHP / GF_Fotonix / CompoundTek / LIGENTEC / HHI_InP / LioniX_InP / LNOI 共 9 个 foundry runset。

**当前实现逻辑**：
- 多 foundry runset 注册表，按材料平台拆分到 `foundry_runsets_soi.py` / `foundry_runsets_inplnoi.py`。
- 每个 runset 含 4-10 条 DRC 规则，阈值来自开源仓库实际源码。

**局限性**：
1. **规则数偏少**：每个 foundry 仅 4-10 条规则，商业 PDK（如 TSMC 28nm）含 1000+ 规则。
2. **无 antenna/step coverage**：未覆盖 CMOS 工艺的 antenna effect 检查。
3. **无 density window**：当前 density 为全局密度，未实现滑窗密度（windowed density）检查。

### 6.3 创新点（标注"创新"）

1. **【创新】AI 辅助 DRC 规则生成**：集成 LLM（GPT-4o / Claude），从 foundry design manual（PDF/文本）自动提取 DRC 规则并生成 PoLaRIS `DRCRule` 对象。
   - **创新逻辑**：KLayout/gdsfactory 均无此能力。LLM 解析 design manual 的几何约束描述（如 "Metal 1 minimum width shall be 0.5 μm"），自动生成 `DRCRule(name="M1_MIN_WIDTH", layer="M1", check_type=WIDTH, threshold_um=0.5)`。
   - **支持理论**：PhIDO（arXiv:2508.14123）已验证 LLM 可解析自然语言光子电路设计意图，准确率 60-80%。DRC 规则文本结构化程度更高，预期准确率 >85%。
   - **案例**：输入 SiEPIC EBeam design manual 段落 "Waveguide minimum width is 400 nm for 220nm SOI platform"，LLM 输出 `DRCRule(name="WG_MIN_WIDTH", layer="WG", check_type=WIDTH, threshold_um=0.4)`。

2. **【创新】DRC 规则冲突自动检测**：在多 foundry runset 合并时，自动检测规则冲突（如同一层两个 foundry 的 width 阈值不同），生成冲突报告。
   - **创新逻辑**：商业 EDA 工具（Calibre/Calibre）不提供此功能，用户需手动审查。PoLaRIS 用图算法（连通分量）检测同层规则冲突。
   - **支持理论**：图论连通分量算法（Cormen et al., "Introduction to Algorithms", MIT Press 2009, Ch. 22）。

3. **【创新】DRC 违规热力图可视化**：将 DRC 违规位置渲染为热力图，叠加于版图之上，支持违规密度可视化。
   - **创新逻辑**：KLayout 仅提供违规列表，无热力图。PoLaRIS 用 KDE（Kernel Density Estimation）渲染违规密度。
   - **支持理论**：核密度估计（Silverman, "Density Estimation for Statistics and Data Analysis", Chapman & Hall 1986）。

## 7. 改进计划路线图

### 步骤 1（W1-W2）：层次化 DRC 引擎实现

- **任务**：实现 `HierarchicalDRCRunner` 类，含 layer-wise BVH 构建、自适应行分块。
- **依赖**：`klayout.db` API、`numpy`（BVH 数组操作）。
- **验收标准**：在 100k 多边形版图上，DRC 速度较 flat 模式提升 ≥3×。
- **风险**：BVH 实现复杂度高，可能需 2 周调试。

### 步骤 2（W2-W3）：`width>` 检查与 sizing API

- **任务**：实现 `Region.sizing(d, mode)` API，用 negative sizing 实现 max-width 检查。
- **依赖**：步骤 1 完成。
- **验收标准**：在 KLayout Issue #2027 的测试用例上，`width>` 检查在 <60s 内完成（KLayout 挂起）。
- **风险**：sizing 算法的边界情况（自相交多边形）需额外处理。

### 步骤 3（W3-W4）：滑窗密度与 antenna 检查

- **任务**：实现 `windowed_density_check(window_size, step)` 与 `antenna_check(gate_layer, metal_layer, ratio)`。
- **依赖**：步骤 1 完成。
- **验收标准**：在 GF180 PDK 测试用例上，density window 检查结果与 KLayout 一致。
- **风险**：滑窗边界处理需对齐 Calibre 规范。

### 步骤 4（W4）：AI 辅助 DRC 规则生成（创新）

- **任务**：实现 `ai_generate_drc_rules(design_manual_text)` 函数，调用 LLM 生成 `DRCRule` 列表。
- **依赖**：LLM API（OpenAI/Anthropic）、步骤 1-3 完成。
- **验收标准**：在 SiEPIC EBeam design manual 上，生成规则准确率 ≥85%。
- **风险**：LLM 输出格式不稳定，需 schema 校验 + 重试机制。

### 步骤 5（W4）：DRC 违规热力图可视化（创新）

- **任务**：实现 `plot_drc_heatmap(violations, layout_bbox)` 函数，用 KDE 渲染违规密度。
- **依赖**：`matplotlib`、`scipy.stats.gaussian_kde`。
- **验收标准**：热力图能清晰展示违规密集区域。
- **风险**：低风险，matplotlib 成熟。
