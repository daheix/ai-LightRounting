## 1. 交付目标摘要

本月目标是 PoLaRIS 深度集成 Flexcompute Tidy3D 云 API，实现 GPU 加速 FDTD 全波电磁仿真。Tidy3D 是基于云原生 + GPU 加速的 FDTD 求解器，相比传统 CPU FDTD（如 MEEP）有 10-5000× 速度提升（Flexcompute 官方数据）。PoLaRIS 现有 `polaris/sim/fdtd_tidy3d_backend.py` 已实现基础 Tidy3D 调用，但缺少：1) 完整 S 参数提取流程；2) 亚像素精度验证；3) 与 MEEP 后端交叉验证；4) 异步任务管理。本月交付：1) 增强 `fdtd_tidy3d_backend.py` 完整 S 参数提取；2) 新增 `tidy3d_async_runner.py` 异步任务管理；3) Tidy3D vs MEEP 交叉验证（误差 < 1e-3）；4) ≥8 个测试用例。完成后 D03 仿真精度 8.5→8.7，综合得分 8.6→8.7。

## 3. 公式与理论依据

### 3.1 FDTD 离散化（Yee 网格）

FDTD 在 Yee 网格上离散 Maxwell 旋度方程：

$$
\nabla \times \mathbf{E} = -\mu \frac{\partial \mathbf{H}}{\partial t}, \quad \nabla \times \mathbf{H} = \epsilon \frac{\partial \mathbf{E}}{\partial t} + \sigma \mathbf{E}
$$

Yee 网格中 E 和 H 场交错排列，时间更新：

$$
H_x^{n+1/2}(i, j+1/2, k+1/2) = H_x^{n-1/2}(i, j+1/2, k+1/2) - \frac{\Delta t}{\mu \Delta y} \left[ E_z^n(i, j+1, k+1/2) - E_z^n(i, j, k+1/2) \right] + \frac{\Delta t}{\mu \Delta z} \left[ E_y^n(i, j+1/2, k+1) - E_y^n(i, j+1/2, k) \right]
$$

### 3.2 CFL 稳定性条件

FDTD 时间步长 $\Delta t$ 必须满足 Courant-Friedrichs-Lewy (CFL) 条件：

$$
\Delta t \leq \frac{1}{c \sqrt{\frac{1}{\Delta x^2} + \frac{1}{\Delta y^2} + \frac{1}{\Delta z^2}}}
$$

3D 立方网格（$\Delta x = \Delta y = \Delta z = \Delta$）简化为：

$$
\Delta t \leq \frac{\Delta}{c \sqrt{3}}
$$

- $c$：真空光速
- $\Delta$：网格尺寸

### 3.3 GPU FDTD 性能模型（Minkov 2024）

GPU FDTD 单步更新时间：

$$
T_{\text{step}} = \max\left(\frac{N_{\text{fl}}}{F}, \frac{N_{\text{bw}} \cdot N_{\text{cell}}}{B}\right)
$$

- $N_{\text{fl}}$：单网格单元更新所需浮点运算数（Yee 网格约 36 FLOPS）
- $F$：GPU 峰值 FLOPS（NVIDIA H100: ~67 TFLOPS FP64）
- $N_{\text{bw}}$：单网格单元字节数（Yee 网格 6 字段 × 4 字节 = 24 字节）
- $B$：GPU 内存带宽（H100: ~3 TB/s）
- $N_{\text{cell}}$：网格单元总数

**性能瓶颈**：FDTD 是内存带宽受限（memory-bound），$N_{\text{bw}} \cdot N_{\text{cell}} / B$ 通常主导。

### 3.4 S 参数提取

Tidy3D 用 ModeMonitor 提取端口模式振幅，S 参数：

$$
S_{ij}(f) = \frac{a_i^{\text{out}}(f)}{a_j^{\text{in}}(f)}
$$

- $a_j^{\text{in}}(f)$：端口 $j$ 的入射模式振幅
- $a_i^{\text{out}}(f)$：端口 $i$ 的出射模式振幅

### 3.5 数值示例

硅光 MMI（10 μm × 10 μm × 2 μm），分辨率 25 cells/λ（λ=1.55 μm，$\Delta \approx 62$ nm）：

- 网格单元数：$N_{\text{cell}} = (10/0.062) \times (10/0.062) \times (2/0.062) \approx 8.4 \times 10^6$
- CPU FDTD（单核）：$T_{\text{step}} \approx 8.4 \times 10^6 \times 36 / 10^9 \approx 0.3$ s，10000 步 ≈ 50 min
- GPU FDTD（H100）：$T_{\text{step}} \approx 8.4 \times 10^6 \times 24 / 3 \times 10^{12} \approx 0.067$ ms，10000 步 ≈ 0.67 s
- 加速比：~4500×

与 Liu & Poon 2025 论文中 Tidy3D 比 Lumerical CPU 快 100-5000× 一致。

## 4. 开源方案缺点分析

### 4.1 MEEP CPU FDTD 速度慢

- **问题描述**: MEEP（MIT 开源 FDTD）仅 CPU，大规模 3D 仿真耗时过长。Liu & Poon 2025 论文显示 MEEP 在 25 cells/λ 分辨率下 3D MMI 仿真需数小时。
- **影响**: 逆向设计迭代次数受限，无法快速探索设计空间。
- **来源 URL**: https://arxiv.org/pdf/2506.16665（Liu & Poon 2025 对比）
- **根因分析**: MEEP 基于 C++ + MPI 并行，但 CPU 核心数有限，无法匹敌 GPU 数千核心。

### 4.2 MEEP GPU 支持不完善

- **问题描述**: MEEP 虽有 GPU 支持（meep-python），但性能远不及 Tidy3D，且需用户自行管理 GPU 资源。
- **影响**: 用户需配置 GPU 环境，门槛高。
- **来源 URL**: https://github.com/NanoComp/meep/issues（多个 GPU 性能问题）
- **根因分析**: MEEP 的 GPU 后端基于 Python + numpy，未深度优化 CUDA kernel。

### 4.3 开源 FDTD 缺少云 API

- **问题描述**: 开源 FDTD（MEEP/Meep）均无云 API，用户需本地安装 + 管理 GPU。
- **影响**: 学术界与初创公司无法负担 GPU 集群，限制大规模仿真。
- **来源 URL**: https://github.com/NanoComp/meep/discussions（云 API 请求）
- **根因分析**: 开源项目缺少商业化云基础设施投入。

### 4.4 Tidy3D 商业云 API 费用高

- **问题描述**: Tidy3D 云 API 按 simulation credit 计费，大规模参数扫描费用高。
- **影响**: 学术研究预算受限，无法大量使用。
- **来源 URL**: https://docs.flexcompute.com/projects/tidy3d/en/latest/pricing.html
- **根因分析**: 商业云服务需覆盖 GPU 折旧 + 运维成本。

## 5. 源代码解读分析

### 5.1 `src/polaris/sim/fdtd_tidy3d_backend.py` — Tidy3D 后端

- **文件路径**: `/workspace/src/polaris/sim/fdtd_tidy3d_backend.py`
- **关键函数/类**: `_build_tidy3d_source`、`_build_tidy3d_monitors`、`_build_tidy3d_simulation`
- **当前实现逻辑**: 构建 Tidy3D PointDipole 光源 + ModeMonitor 列表，提交到 Flexcompute 云端求解。需 `TIDY3D_API_KEY` 环境变量，无 key 时明确报错（不 fall-back）。
- **局限性**:
  1. 仅支持 PointDipole 光源，缺少 ModeSource/GaussianBeam
  2. S 参数提取流程不完整（缺少模式归一化）
  3. 同步阻塞调用，无异步任务管理
  4. 缺少亚像素精度验证
- **改进点**: 增强 ModeSource 支持、完整 S 参数提取、异步任务管理、亚像素验证。

### 5.2 `src/polaris/sim/fdtd_simulator.py` — FDTD 统一接口

- **文件路径**: `/workspace/src/polaris/sim/fdtd_simulator.py`
- **关键函数/类**: `FDTDBackend`（枚举：MEEP/TIDY3D/ANALYTICAL）、`FDTDConfig`、`FDTDResult`
- **当前实现逻辑**: 统一 FDTD 接口，支持三种后端切换。自动将 `3dtool/wheels/` 加入 sys.path 以加载 Tidy3D。
- **局限性**:
  1. 后端切换需重新构建仿真，无缓存
  2. 缺少后端交叉验证工具
- **改进点**: 新增后端交叉验证函数 `cross_validate_backends`。

### 5.3 `src/polaris/sim/fdtd_meep_backend.py` — MEEP 后端

- **文件路径**: `/workspace/src/polaris/sim/fdtd_meep_backend.py`
- **关键函数/类**: MEEP 后端调用
- **当前实现逻辑**: 调用 MEEP Python API 构建 FDTD 仿真，CPU 后端。
- **局限性**: CPU 速度慢，无 GPU 加速。
- **改进点**: 作为 Tidy3D 的交叉验证基准（精度对比）。

### 5.4 `src/polaris/sim/adjoint_optimizer.py` — Adjoint 框架

- **文件路径**: `/workspace/src/polaris/sim/adjoint_optimizer.py`
- **关键函数/类**: `OptimizationBackend`（枚举：MEEP/TIDY3D/ANALYTICAL）、`AdjointConfig`、`AdjointOptimizer`
- **当前实现逻辑**: 已定义 TIDY3D 后端枚举，但实际调用未完整实现。
- **局限性**: TIDY3D adjoint 调用未完整实现。
- **改进点**: R29 完整实现 Tidy3D adjoint 后端。

### 6.1 复刻清单（100% 对齐 Tidy3D）

| Tidy3D 能力 | PoLaRIS 现状 | R27 复刻方案 |
|------------|--------------|--------------|
| 云 API 调用（web.run） | 基础实现 | 增强 + 异步任务管理 |
| ModeSource/PointDipole/GaussianBeam | 仅 PointDipole | 新增 ModeSource/GaussianBeam |
| ModeMonitor S 参数提取 | 基础实现 | 完整模式归一化 + S 参数矩阵 |
| 亚像素精度（subpixel averaging） | 无 | 验证 Tidy3D 亚像素精度 |
| 多 GPU 并行 | 无（云端自动） | 异步任务管理多仿真并行 |
| 与 MEEP 交叉验证 | 无 | 新增 `cross_validate_backends` |
| 材料库（material_library） | 无 | 直接使用 Tidy3D 材料库 |
| PML 边界条件 | 无 | 配置 PML/Bloch/Periodic |
| 频率扫描 | 无 | 多波长 ModeMonitor |

### 6.2 改进点（超越 Tidy3D）

1. **多后端自动切换**（创新）：Tidy3D 仅支持自有云后端，PoLaRIS 实现多后端自动切换（Tidy3D 云 + MEEP 本地 + ANALYTICAL），根据器件规模自动选择最优后端。
   - 创新逻辑：器件网格单元数 < 10^5 用 ANALYTICAL，10^5-10^7 用 MEEP，> 10^7 用 Tidy3D
   - 支持理论：FDTD 性能模型（Minkov 2024）
   - 预期收益：小器件仿真成本降至 0（用 ANALYTICAL），大器件享受 Tidy3D GPU 加速

2. **本地结果缓存**（创新）：Tidy3D 每次仿真都需上传到云端，PoLaRIS 实现本地结果缓存（基于器件参数哈希），相同参数直接返回缓存结果。
   - 创新逻辑：器件参数 → SHA256 哈希 → 缓存 key
   - 支持理论：哈希函数抗碰撞性
   - 预期收益：逆向设计迭代中重复仿真节省 30-50% 云 API 费用

3. **批量仿真优化**（创新）：Tidy3D 单次仿真提交，PoLaRIS 实现批量仿真（参数扫描）并行提交，利用云端多 GPU 并行。
   - 创新逻辑：参数扫描 → 异步任务列表 → 并行提交
   - 支持理论：Amdahl 定律（并行加速比）
   - 预期收益：参数扫描速度提升 5-10×

### 6.3 创新点标注

- **创新 1**: 多后端自动切换（基于器件规模智能选择）
- **创新 2**: 本地结果缓存（节省云 API 费用）
- **创新 3**: 批量仿真并行提交（参数扫描加速）
