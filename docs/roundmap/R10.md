## 3. 公式与理论依据

### 3.1 A* 代价函数

A* 算法的核心代价函数：

$$
f(n) = g(n) + h(n)
$$

**变量定义**：
- $f(n)$：节点 $n$ 的总估价
- $g(n)$：从起点到节点 $n$ 的实际代价
- $h(n)$：从节点 $n$ 到终点的启发式估计代价

**最优性条件**：$h(n)$ 必须 admissible（不高估实际代价），即 $h(n) \leq h^*(n)$，其中 $h^*(n)$ 为实际最小代价。

**推导来源**：Hart, Nilsson & Raphael, IEEE TSSC 1968。

**数值示例**：曼哈顿距离启发 $h(n) = |x_n - x_{\text{goal}}| + |y_n - y_{\text{goal}}|$，在 4-邻接网格上 admissible。

### 3.2 Jump Point Search 剪枝

JPS 通过"跳跃"扩展节点，减少 A* 节点扩展数：

$$
N_{\text{JPS}} \approx \frac{N_{\text{A*}}}{10} \sim \frac{N_{\text{A*}}}{3}
$$

**变量定义**：
- $N_{\text{A*}}$：A* 节点扩展数
- $N_{\text{JPS}}$：JPS 节点扩展数

**推导来源**：Harabor & Grastien, AAAI 2011。

**适用条件**：均匀代价网格，4/8-邻接。

### 3.3 弯曲半径约束

光波导布线需满足最小弯曲半径约束（避免弯曲损耗过大）：

$$
R \geq R_{\min}
$$

**变量定义**：
- $R$：实际弯曲半径
- $R_{\min}$：最小弯曲半径（SOI 典型 5μm，SiN 典型 50μm）

**转弯前直行步数**：

$$
n_{\text{straight}} = \max\left(2, \left\lceil \frac{R_{\min}}{\Delta} \right\rceil\right)
$$

**变量定义**：
- $\Delta$：网格尺寸

**推导来源**：PoLaRIS `GridRouter.__init__`（`/workspace/src/polaris/router/waveguide_router.py` 第 134-137 行）；Fujisawa et al., Opt. Express 2017。

### 3.4 欧拉弯曲（Clothoid）参数化

欧拉弯曲的曲率随弧长线性变化：

$$
\kappa(s) = \frac{s}{R \cdot L_{\text{clothoid}}}
$$

$$
x(s) = \int_0^s \cos\left(\frac{\pi t^2}{2 R L_{\text{clothoid}}}\right) dt
$$

$$
y(s) = \int_0^s \sin\left(\frac{\pi t^2}{2 R L_{\text{clothoid}}}\right) dt
$$

**变量定义**：
- $\kappa(s)$：弧长 $s$ 处的曲率
- $R$：最终弯曲半径
- $L_{\text{clothoid}}$：欧拉过渡段长度

**推导来源**：Fujisawa et al., Opt. Express 2017；Rizzo et al., Optics Letters 2023。

### 3.5 等长路径匹配

MZI 等干涉器件需等长波导臂，等长匹配约束：

$$
|L_1 - L_2| \leq \epsilon
$$

**变量定义**：
- $L_1, L_2$：两臂波导长度
- $\epsilon$：长度容差（典型 0.1μm）

**S 弯补偿长度**：

$$
L_{\text{S-bend}} = \Delta L + L_{\text{baseline}}
$$

**推导来源**：PoLaRIS `equalize_length` 函数（`/workspace/src/polaris/router/path_geometry.py`）。

### 3.6 Dubins Path

Dubins path 是两点间最短曲率约束路径：

$$
L_{\text{Dubins}} = \min\left(L_{\text{LSL}}, L_{\text{RSR}}, L_{\text{LSR}}, L_{\text{RSL}}, L_{\text{RLR}}, L_{\text{LRL}}\right)
$$

**变量定义**：
- $L/R$：左转/右转圆弧
- $S$：直线段

**推导来源**：Dubins, "On Curves of Minimal Length with a Constraint on Average Curvature", American J. Mathematics 1957。

## 4. 开源方案缺点分析

### 缺点 1：gdsfactory `route_astar` 性能瓶颈

- **问题描述**: gdsfactory `route_astar` 在大网格（>1000×1000）上性能差，因 `networkx.astar_path` 纯 Python 实现且无 JPS 剪枝。
- **影响**: 大规模 PIC 布线耗时（典型 10s+/route）。
- **来源 URL**: https://blog.csdn.net/gitblog_07066/article/details/148823570
- **根因分析**: `networkx.astar_path` 用 Python 堆，无 JPS 剪枝，节点扩展数大。gdsfactory 7.27.0 changelog 标注"Improve get route astar #2752"，说明性能是长期痛点。

### 缺点 2：gdsfactory 非曼哈顿布线 1nm 间隙问题

- **问题描述**: gdsfactory 非曼哈顿布线（`route_bundle_all_angle`）因网格 snapping 产生 1nm 间隙，需 `flatten_offgrid_references=True` 规避。
- **影响**: 1nm 间隙导致 DRC 失败或仿真误差。
- **来源 URL**: https://gdsfactory.github.io/gdsfactory7/notebooks/04_routing_non_manhattan.html
- **根因分析**: GDSII 格式用整数坐标，非曼哈顿角度的浮点坐标 snapping 到整数产生间隙。

### 缺点 3：gdsfactory `route_bundle` 端口朝向约束

- **问题描述**: `route_bundle` 要求所有目标端口朝向相同，否则报错"RouteWarning: Not enough room to route between ports"。
- **影响**: 异构朝向端口需手动分批路由，流程繁琐。
- **来源 URL**: https://gdsfactory.github.io/gdsfactory/notebooks/04_routing.html
- **根因分析**: `route_bundle` 的 river/bus 路由算法假设端口朝向一致，无朝向自适应。

### 缺点 4：gdsfactory 无 GPU 加速布线

- **问题描述**: gdsfactory 布线纯 CPU，无 GPU 加速，大规模 PIC（>1000 端口）布线耗时。
- **影响**: 大规模 PIC 设计周期长。
- **来源 URL**: https://github.com/gdsfactory/gdsfactory
- **根因分析**: gdsfactory 基于 `networkx`（CPU）与 `klayout.db`（C++ 单线程），无 GPU 路径。

### 缺点 5：gdsfactory 无 AI 辅助布线

- **问题描述**: gdsfactory 布线参数（separation/bend/separator）需手动调优，无 AI 辅助。
- **影响**: 新手难以选择最优参数，布线质量依赖经验。
- **来源 URL**: https://gdsfactory.github.io/gdsfactory/notebooks/04_routing.html
- **根因分析**: gdsfactory 无 ML 模型集成，参数选择依赖用户经验。

## 5. 源代码解读分析

### 5.1 文件：`/workspace/src/polaris/router/waveguide_router.py`

**关键函数**：

- `GridRouter`：A* 网格布线器基线，含 `route(start, goal)` / `add_obstacle(gx, gy, gw, gh)`。
- `WaveguideRouter`：波导约束布线器，封装 `GridRouter` + 弯曲半径/间距约束。
- `route_connection(component, port1, port2, config)`：单端口对布线便捷函数。
- `route_curvy_connection(...)`：曲线感知布线（对标 LiDAR）。

**当前实现逻辑**：
- A* 用 `heapq` 优先队列，4-邻接（E/W/N/S）。
- 弯曲半径约束：转弯前须直行 ≥`min_bend_steps` 步。
- 障碍栅格：`ObstacleGrid` 自适应稠密 numpy / 稀疏 set 存储。
- 路径优化：紧致启发式 + tie-breaker（Red Blob Games 方案）。

**局限性**：
1. **无 JPS 剪枝**：A* 节点扩展数大，性能瓶颈。
2. **无 bundle 布线**：仅单端口对布线，无 `route_bundle` 多端口对布线。
3. **无非曼哈顿布线**：仅 4-邻接（曼哈顿），无任意角度布线。
4. **无 Dubins path**：未实现 Dubins path 曲线布线。
5. **无 auto_taper**：未实现自动 taper 插入。
6. **无 path length match**：未实现等长匹配布线（仅有 `equalize_length` 几何工具）。
7. **无 GPU 加速**：纯 CPU。

**改进点**：
- 新增 `JPSRouter` 类，实现 JPS 剪枝。
- 新增 `route_bundle(component, ports1, ports2, **kwargs)` 函数。
- 新增 `AllAngleRouter` 类，实现非曼哈顿布线（对标 `route_bundle_all_angle`）。
- 新增 `dubins_path(start, end, radius)` 函数。
- 新增 `auto_taper(route, taper_length)` 函数。
- 新增 `route_bundle_path_length_match(...)` 函数。

1. **【创新】GPU 加速 A* 布线**：用 `torch` 或 `cupy` 实现 GPU 并行 A*，预期较 CPU `networkx.astar_path` 快 10-50×。
   - **创新逻辑**：gdsfactory 无 GPU 布线（缺点 4），PoLaRIS 用 GPU 并行扩展多个候选节点。
   - **支持理论**：GPU 并行前缀和（X-Check 论文 ICCAD 2022 的并行扫描线思想）。
   - **案例**：1000×1000 网格上，CPU A* 10s，GPU A* 预期 0.5s。

2. **【创新】AI 辅助布线参数调优**：用 RL agent 学习最优布线参数（separation/bend/separator），自动适应不同 PIC 拓扑。
   - **创新逻辑**：gdsfactory 参数手动调优（缺点 5），PoLaRIS 用 RL 自动学习。
   - **支持理论**：PPO 算法（Schulman et al., arXiv:1707.06347 2017）；PoLaRIS 已有 `routing_env.py` RL 环境。
   - **案例**：MZI 阵列布线，RL agent 学习 separation=5μm, bend=euler, separator=manhattan，布线成功率从 92% 提升至 98%。

3. **【创新】自适应交叉插入**：在布线过程中自适应插入波导交叉（crossing），最小化交叉数同时保证布线成功率。
   - **创新逻辑**：gdsfactory 无自适应交叉插入，PoLaRIS 用启发式（ congestion > threshold 时插入交叉）。
   - **支持理论**：PoLaRIS arXiv:2507.22301 提及 "adaptive crossing insertion"。

## 7. 改进计划路线图

### 步骤 1（W1-W2）：JPS 剪枝加速

- **任务**：实现 `JPSRouter` 类，含 `_jump` / `_get_jump_successors` 方法。
- **依赖**：`GridRouter` 基类、Harabor & Grastien AAAI 2011 算法。
- **验收标准**：在 1000×1000 网格上，JPS 较 A* 加速 ≥5×，路径长度一致。
- **风险**：JPS 在非均匀代价网格上需扩展（当前假设均匀代价）。

### 步骤 2（W2-W3）：Bundle 布线

- **任务**：实现 `route_bundle(component, ports1, ports2, **kwargs)` 函数，含端口排序、防碰撞、separation 约束。
- **依赖**：`GridRouter` / `JPSRouter`。
- **验收标准**：在 6×6 端口对布线上，成功率 100%，无碰撞。
- **风险**：端口排序算法需对齐 gdsfactory `sort_ports` 逻辑。

### 步骤 3（W3）：非曼哈顿布线

- **任务**：实现 `AllAngleRouter` 类，支持任意角度端口布线，含 bend handle 计算。
- **依赖**：`curvy_router.py` 现有代码、LiDAR ISPD 2025 算法。
- **验收标准**：在 gdsfactory `aar_simple.pic.yml` 测试用例上，布线结果与 gdsfactory 一致。
- **风险**：1nm 间隙问题需用 `flatten_offgrid_references` 规避。

### 步骤 4（W3-W4）：Dubins path + auto_taper + path length match

- **任务**：实现 `dubins_path` / `auto_taper` / `route_bundle_path_length_match`。
- **依赖**：`path_geometry.py` 现有工具。
- **验收标准**：Dubins path 在 R=5μm 下长度误差 <0.1μm；path length match 在 ±0.5μm 容差内。
- **风险**：Dubins path 6 种组合（LSL/RSR/LSR/RSL/RLR/LRL）需全部实现。

### 步骤 5（W4）：GPU 加速 A* + AI 参数调优（创新）

- **任务**：实现 `GPURouter` 类（torch/cupy）与 RL 参数调优 agent。
- **依赖**：`torch`（已安装）、`routing_env.py`。
- **验收标准**：GPU A* 较 CPU 加速 ≥10×；RL agent 在 MZI 阵列上布线成功率 ≥98%。
- **风险**：GPU A* 实现复杂度高，可能需 2 周。
