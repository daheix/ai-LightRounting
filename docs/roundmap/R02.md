## 1. 交付目标摘要

本路标目标是在光子电路仿真层面 100% 对齐开源工具 simphony（BYU CamachoLab 开发）。simphony 是首个使用子网络增长算法的开源光子电路仿真框架，论文发表于 IEEE Computing in Science & Engineering（2021），对比 Lumerical INTERCONNECT 实现 20 倍加速。PoLaRIS 当前已在 `simulator.py` 中实现 `CircuitSimulator` 类，并通过 `simphony_models()` 函数映射 simphony SiEPIC 模型库，但与 simphony 相比仍存在差距：（1）缺少 simphony 的 SPICE 风格网表解析器；（2）缺少 SiEPIC-Tools KLayout 集成；（3）器件模型库覆盖不足（simphony 提供 waveguide、y_branch、directional_coupler、grating_coupler、half_ring、terminator、taper 等 7+ SiEPIC 模型）；（4）缺少群延迟和色散分析。本月交付目标为：完成 simphony 核心 API 的 100% 复刻，新增 SiEPIC 完整模型库，实现群延迟分析，综合得分从 6.3 提升至 6.5。

## 3. 公式与理论依据

### 3.1 光子电路传递函数 H(ω)

对于线性时不变光子电路，传递函数定义为输出与输入的频域比：

$$H(\omega) = \frac{Y(\omega)}{X(\omega)} = S_{21}(\omega)$$

其中：
- $\omega = 2\pi c / \lambda$ 为角频率
- $S_{21}(\omega)$ 为从端口 1 到端口 2 的 S 参数
- $X(\omega)$、$Y(\omega)$ 为输入、输出信号的傅里叶变换

**推导来源**: 标准信号与系统理论，Oppenheim & Willsky, "Signals and Systems"。
**适用条件**: 线性时不变系统，单输入单输出（SISO）。
**数值示例**: MZI 传递函数 $H(\omega) = \frac{1}{2}(1 + e^{j\omega\tau})$，其中 $\tau = n_g L / c$ 为延迟臂时延。

### 3.2 群延迟 τ_g

群延迟定义为传递函数相位对角频率的负导数：

$$\tau_g = -\frac{d\phi(\omega)}{d\omega} = -\frac{d}{d\omega}\arg[H(\omega)]$$

其中 $\phi(\omega) = \arg[H(\omega)]$ 为传递函数的相位。

**推导来源**: 光纤通信标准理论，Agrawal, "Fiber-Optic Communication Systems"。
**适用条件**: 窄带信号，传递函数在信号带宽内近似线性相位。
**数值示例**: 波导长度 $L=100\mu m$，$n_g=4.0$：$\tau_g = n_g L / c = 4.0 \times 100\times10^{-6} / (3\times10^8) \approx 1.33$ ps。

### 3.3 传输矩阵法（TMM）

对于多层结构（如 DBR 反射镜、耦合器），传输矩阵法将每层表示为 2×2 矩阵：

$$\begin{bmatrix} E_{out}^+ \\ E_{out}^- \end{bmatrix} = \mathbf{M}_N \mathbf{M}_{N-1} \cdots \mathbf{M}_1 \begin{bmatrix} E_{in}^+ \\ E_{in}^- \end{bmatrix}$$

其中每层传输矩阵：

$$\mathbf{M}_i = \begin{bmatrix} \cos\delta_i & j\sin\delta_i / \eta_i \\ j\eta_i\sin\delta_i & \cos\delta_i \end{bmatrix}$$

$\delta_i = 2\pi n_i d_i / \lambda$ 为相位厚度，$\eta_i$ 为导纳。

**推导来源**: Macleod, "Thin-Film Optical Filters"；Born & Wolf, "Principles of Optics"。
**适用条件**: 一维多层结构，平面波入射。
**数值示例**: SiO2/Si DBR 反射镜，每层 λ/4 厚度，反射率 > 99%。

### 3.4 环谐振器传输函数（全通型）

全通型单总线环谐振器的传输函数：

$$T(\lambda) = \frac{t - a \cdot e^{i\phi}}{1 - t \cdot a \cdot e^{i\phi}}$$

其中：
- $t = \sqrt{1 - \kappa}$ 为自耦合系数（直通振幅）
- $\kappa$ 为功率耦合系数
- $a = 10^{-\alpha L / 20}$ 为环内单圈振幅衰减
- $\alpha$ 为波导损耗系数（dB/m）
- $L = 2\pi R$ 为环周长
- $\phi = 2\pi n_{eff} L / \lambda$ 为环内单圈相位

**推导来源**: Yariv, "Optical Electronics in Modern Communications", Oxford 1997, §10.5；Chrostowski 2015 §4.5。
**适用条件**: 弱耦合（$\kappa \ll 1$），单模工作，环内无背向反射。
**数值示例**: $R=10\mu m$，$n_{eff}=2.4$，$\kappa=0.01$，$\alpha=0.1$ dB/cm：FSR = $c/(n_g \cdot 2\pi R) \approx 5.96$ THz ≈ 47.7 nm @ 1550nm。

### 3.5 MZI 传输函数

双臂 MZI 的传输函数：

$$H_{MZI}(\lambda) = \frac{1}{2}\left(e^{j\phi_1} + e^{j\phi_2}\right) = \cos\left(\frac{\Delta\phi}{2}\right) \cdot e^{j(\phi_1+\phi_2)/2}$$

其中 $\Delta\phi = \phi_1 - \phi_2 = 2\pi n_{eff} \Delta L / \lambda$ 为两臂相位差，$\Delta L$ 为臂长差。

**推导来源**: 标准干涉理论；Chrostowski 2015 §3.2。
**适用条件**: 理想 3dB 分束器，无损耗，单模。
**数值示例**: $\Delta L = 100\mu m$，$n_g=4.0$：FSR = $c/(n_g \Delta L) \approx 7.5$ THz ≈ 60 nm @ 1550nm。

### 3.6 自由光谱范围（FSR）

环谐振器和 MZI 的自由光谱范围：

$$FSR = \frac{c}{n_g \cdot L_{opt}}$$

其中 $L_{opt}$ 为光学路径长度（环周长或 MZI 臂长差），$n_g$ 为群折射率。

**推导来源**: Chrostowski 2015 §4.4。
**适用条件**: 色散可忽略（窄带分析）。
**数值示例**: 见 3.4 和 3.5。

## 4. 开源方案缺点分析

### 4.1 simphony 仅支持频域
- **问题描述**: simphony 仅支持频域 S 参数仿真，无法进行时域仿真。对于需要时域响应的应用（如光脉冲传播、瞬态分析），用户必须使用其他工具。
- **影响**: 限制了 simphony 在超快光子学、光信号处理等场景中的应用。
- **来源 URL**: https://simphonyphotonics.readthedocs.io/en/stable/index.html （文档明确指出 simphony 使用"subnetwork growth algorithms"进行频域仿真）；https://arxiv.org/abs/2009.05146 （论文 §2 仅讨论频域 S 参数）
- **根因分析**: simphony 的核心数据结构基于频域 S 参数，子网络增长算法在频域逐点求解。时域仿真需要状态空间模型，与 simphony 的架构不兼容。

### 4.2 simphony 器件库有限
- **问题描述**: simphony 仅提供 SiEPIC 模型库（7 个器件：waveguide、y_branch、directional_coupler、grating_coupler、half_ring、terminator、taper），缺少其他工艺平台（如 LNOI、InP、SiN）的模型。用户需要自行实现自定义模型。
- **影响**: 限制了 simphony 在多工艺平台设计中的应用，用户被迫为每个工艺平台重新实现模型。
- **来源 URL**: https://simphonyphotonics.readthedocs.io/en/stable/ （文档仅列出 SiEPIC 库）；https://camacholab.byu.edu/simphony-rea （新闻指出 simphony 主要贡献者有限）
- **根因分析**: simphony 由 BYU CamachoLab 维护，资源有限，聚焦 SiEPIC 工艺平台。SiPANN 提供更丰富的模型但依赖 TensorFlow。

### 4.3 simphony 无 GPU 加速
- **问题描述**: simphony 虽然可选依赖 JAX，但其核心子网络增长算法使用纯 numpy 实现，无法利用 GPU 加速。对于大规模电路（如 64×64 光子神经网络），仿真速度慢。
- **影响**: 大规模电路仿真耗时数分钟到数小时，无法满足迭代优化需求。
- **来源 URL**: https://simphonyphotonics.readthedocs.io/en/stable/index.html （文档提到"If you are using a machine with a GPU, you should follow the instructions for JAX installation"，但核心算法未使用 JAX）
- **根因分析**: simphony 的子网络增长算法使用 Python 循环逐端口消元，无法向量化。sax 通过 KLU 后端和 JAX 解决此问题。

### 4.4 simphony 无 AI/ML 集成
- **问题描述**: simphony 不支持自动微分，无法直接用于梯度优化和机器学习。用户需要手动实现有限差分梯度计算。
- **影响**: 无法进行端到端可微分光子电路优化，限制了 AI 驱动光子设计的应用。
- **来源 URL**: https://arxiv.org/abs/2411.13715 （SimPhony 论文指出需要"seamless integration with model training framework for hardware/software co-simulation"，simphony 无此能力）
- **根因分析**: simphony 的核心数据结构使用 numpy 而非 jax.numpy，无法追踪计算图。sax 通过 JAX 解决此问题。

### 4.5 simphony 网表格式与 SPICE 不完全兼容
- **问题描述**: simphony 使用自定义网表格式（`Subcircuit`、`Term`、`Connector` 类），虽然文档称"SPICE-like method"，但与标准 SPICE 语法不兼容。用户无法直接导入 SPICE 网表。
- **影响**: 与电子 EDA 工具（如 ngspice、LTspice）互操作性差，电子-光子协同仿真困难。
- **来源 URL**: https://simphonyphotonics.readthedocs.io/en/stable/tutorials/intro.html （教程使用 Python API 而非 SPICE 语法）
- **根因分析**: simphony 的网表格式设计优先考虑 Python API 易用性，而非 SPICE 兼容性。Synopsys 白皮书指出"electrical circuit languages are not robust enough for photonics"。

3. **增加波长相关 neff**: 使用 Sellmeier 方程实现硅波导色散模型，$n_{eff}(\lambda) = \sqrt{A + B/\lambda^2 + C/\lambda^4}$。

### 6.3 创新点（标注"创新"）

1. **创新：多工艺平台模型库** — PoLaRIS 在 simphony SiEPIC 模型基础上，增加 SOI、SiN、LNOI、InP 四个工艺平台的模型库（已有 `/workspace/src/polaris/pdk/soi/`、`/workspace/src/polaris/pdk/sin/`、`/workspace/src/polaris/pdk/lnoi/`、`/workspace/src/polaris/pdk/inp/` 目录），simphony 仅支持 SiEPIC。
   - **创新逻辑**: 通过统一的 `ModelFunc` 协议和参数集合 dataclass，实现多工艺平台模型的统一接口。
   - **支持理论**: PoLaRIS 已有 PDK 模块（`src/polaris/pdk/`），支持多工艺平台是架构优势。
   - **案例**: 用户可在同一仿真器中混合使用 SOI 波导和 LNOI 调制器，simphony 不支持。

2. **创新：自动 FSR 和 Q 因子提取** — PoLaRIS 在 `analyze_dispersion()` 中自动从传输谱提取 FSR、Q 因子、3dB 带宽、消光比等指标，simphony 需用户手动计算。
   - **创新逻辑**: 使用峰值检测和 Lorentzian 拟合自动提取谐振参数。
   - **支持理论**: 标准谐振分析理论（Yariv 1997 §10.5）。
   - **案例**: 对环谐振器传输谱调用 `analyze_dispersion()`，自动返回 `{FSR: 47.7nm, Q: 12000, ER: 25dB, BW_3dB: 0.13nm}`。

3. **创新：SiEPIC JSON 网表自动解析** — PoLaRIS 自动解析 SiEPIC-Tools KLayout 导出的 JSON 网表（`/workspace/data/benchmarks/siepic_netlists/` 已有 7 个测试网表），simphony 需手动构建电路。
   - **创新逻辑**: 通过 JSON schema 解析 SiEPIC 网表格式，自动转换为 PoLaRIS 内部网表。
   - **支持理论**: SiEPIC-Tools 是 KLayout 的开源扩展，其网表格式有公开规范。
   - **案例**: 直接加载 `MZI1.json` 进行仿真，无需手动编写 Python 代码。

## 7. 改进计划路线图

### 7.1 步骤 1（Week 1）：实现 simphony 兼容 API
- **依赖**: R01 完成
- **验收标准**: 新增 `Subcircuit`、`Term`、`Connector` 类，通过 simphony 风格 API 构建电路测试
- **风险**: API 设计需与 simphony 完全一致，否则破坏兼容性

### 7.2 步骤 2（Week 1-2）：新增 SiEPIC 缺失模型
- **依赖**: 步骤 1
- **验收标准**: 新增 `half_ring_s()`、`taper_s()`，与 simphony SiEPIC 模型对比误差 < 1e-10
- **风险**: half_ring 模型的耦合系数计算复杂

### 7.3 步骤 3（Week 2）：实现群延迟和色散分析
- **依赖**: 步骤 2
- **验收标准**: `group_delay()` 通过波导解析解验证（$\tau_g = n_g L / c$）；`analyze_dispersion()` 通过环谐振器 FSR 验证
- **风险**: 峰值检测算法的鲁棒性

### 7.4 步骤 4（Week 3）：实现 add-drop 型环谐振器
- **依赖**: 步骤 2
- **验收标准**: add-drop 型环谐振器通过功率守恒测试（through + drop = 1）；与 simphony half_ring 对比
- **风险**: 双总线耦合的数学推导复杂

### 7.5 步骤 5（Week 3）：SiEPIC JSON 网表解析器
- **依赖**: 步骤 1
- **验收标准**: 解析 `/workspace/data/benchmarks/siepic_netlists/` 全部 7 个网表，仿真结果与手动构建一致
- **风险**: SiEPIC JSON 格式的边界情况

### 7.6 步骤 6（Week 4）：建立 simphony 回归测试基准
- **依赖**: 步骤 1-5
- **验收标准**: 10+ 测试用例（含 MZI、Ring、Clements 网格、WDM 滤波器）与 simphony 结果对比，相对误差 < 1e-10
- **风险**: simphony 版本更新可能改变参考结果
