## 3. 公式与理论依据

### 3.1 反向模式自动微分（链式法则）

对于复合函数 $f(x) = f_n \circ f_{n-1} \circ \cdots \circ f_1(x)$，反向模式 AD 计算梯度：

$$\frac{df}{dx} = \frac{\partial f_n}{\partial f_{n-1}} \cdot \frac{\partial f_{n-1}}{\partial f_{n-2}} \cdots \frac{\partial f_1}{\partial x}$$

反向模式从输出向输入反向传播梯度：

$$\bar{v}_i = \sum_{j \in \text{successors}(i)} \bar{v}_j \cdot \frac{\partial v_j}{\partial v_i}$$

其中 $\bar{v}_i$ 为中间变量 $v_i$ 的伴随变量（adjoint）。

**推导来源**: Baydin et al., "Automatic Differentiation in Machine Learning: a Survey", JMLR 2018；Frostig et al. 2021。
**适用条件**: 可微函数，计算图无环。
**数值示例**: $f(x) = \sin(x^2)$，$f'(x) = 2x\cos(x^2)$，反向模式计算量与 $x$ 维度无关。

### 3.2 向量-雅可比积（VJP）

对于函数 $f: \mathbb{R}^n \to \mathbb{R}^m$，VJP 定义为：

$$\text{VJP}(\mathbf{v}) = \mathbf{J}^T \cdot \mathbf{v}$$

其中 $\mathbf{J} \in \mathbb{R}^{m \times n}$ 为雅可比矩阵，$\mathbf{v} \in \mathbb{R}^m$ 为输出空间的向量。

JAX 的 `jax.grad(f)` 通过 VJP 实现：先前向计算 $f(x)$，再反向计算 VJP(1)。

**推导来源**: Frostig et al. 2021；Griewank & Walther, "Evaluating Derivatives", SIAM 2008。
**适用条件**: 可微函数。
**数值示例**: $f: \mathbb{R}^3 \to \mathbb{R}$，VJP 计算量 O(n)，比完整雅可比 O(n²) 高效。

### 3.3 雅可比-向量积（JVP）

JVP 定义为：

$$\text{JVP}(\mathbf{v}) = \mathbf{J} \cdot \mathbf{v}$$

JAX 的 `jax.jacfwd` 通过 JVP 实现：对每个标准基向量调用 JVP。

**推导来源**: Frostig et al. 2021。
**适用条件**: 可微函数。
**数值示例**: $f: \mathbb{R}^n \to \mathbb{R}^m$，JVP 计算量 O(m)，前向模式 AD。

### 3.4 XLA 编译

JAX 通过 XLA（Accelerated Linear Algebra）编译器将计算图编译为优化代码：

1. **追踪（Tracing）**: JAX 追踪 Python 函数，构建 HLO（High Level Optimizer）IR
2. **优化（Optimization）**: XLA 应用代数优化、融合、内存布局优化
3. **代码生成（Code Generation）**: 生成目标平台代码（CPU、GPU、TPU）

JIT 编译的关键约束：函数必须为纯且静态组合（PSC），无副作用。

**推导来源**: Frostig et al. 2018（SysML）；XLA 文档。
**适用条件**: 纯函数，静态形状。
**数值示例**: 矩阵乘法 JIT 编译后，XLA 融合为单个 GPU kernel，避免中间内存分配。

### 3.5 GPU 并行（pmap）

JAX 的 `pmap` 实现数据并行：

$$\text{pmap}(f)(\mathbf{x}_1, \mathbf{x}_2, \ldots, \mathbf{x}_N) = [f(\mathbf{x}_1), f(\mathbf{x}_2), \ldots, f(\mathbf{x}_N)]$$

每个设备执行 $f$ 的副本，处理不同数据分片。

**推导来源**: JAX 官方文档；数据并行理论。
**适用条件**: 多设备（GPU/TPU），数据可分片。
**数值示例**: 8 GPU 并行，蒙特卡洛分析 8 个电路变体，加速 8 倍。

### 3.6 光子电路梯度优化

光子电路优化问题：

$$\min_{\theta} \mathcal{L}(\theta) = \min_{\theta} \|S_{target} - S_{circuit}(\theta)\|^2$$

其中 $\theta$ 为电路参数（如波导长度、耦合系数），$S_{circuit}(\theta)$ 为电路 S 参数。

梯度下降更新：

$$\theta_{t+1} = \theta_t - \eta \cdot \nabla_\theta \mathcal{L}(\theta_t)$$

JAX 的 `jax.grad` 自动计算 $\nabla_\theta \mathcal{L}$。

**推导来源**: 标准优化理论；sax 文档。
**适用条件**: 可微 S 参数模型。
**数值示例**: MZI 臂长优化，目标特定传输谱，梯度下降 100 次迭代收敛。

## 4. 开源方案缺点分析

### 4.1 sax 强制依赖 JAX，安装包体积大
- **问题描述**: sax 强制依赖 JAX（包括 jaxlib），安装包体积大（jaxlib 约 200MB+），在无 GPU 环境下仍需安装完整 JAX。对于仅需频域仿真的用户，依赖过重。
- **影响**: 部署成本高，CI/CD 流水线构建慢，嵌入式或资源受限环境难以使用。
- **来源 URL**: https://pypi.org/project/sax/ （依赖列表包含 jax、jaxlib、klujax）
- **根因分析**: sax 的核心数据结构（SDict）使用 jax.numpy 而非 numpy，无法降级为纯 numpy 模式。

### 4.2 sax JIT 编译首次开销大
- **问题描述**: sax 的 JIT 编译首次调用时需要追踪和编译，耗时数秒到数十秒。对于小规模电路或交互式使用，首次开销可能超过仿真本身。
- **影响**: 交互式开发和快速原型设计体验差。
- **来源 URL**: https://docs.jax.dev/en/latest/jax-101/02-jitting.html （JAX JIT 文档提及首次编译开销）
- **根因分析**: XLA 编译需要构建和优化 HLO IR，开销与计算图复杂度相关。

### 4.3 sax 自动微分对非光滑模型失效
- **问题描述**: sax 的自动微分依赖 JAX 的 VJP，对于非光滑模型（如含 abs、sign 的模型）或离散参数（如器件类型选择），梯度计算失效或错误。
- **影响**: 优化结果不可信。
- **来源 URL**: https://docs.jax.dev/en/latest/notebooks/autodiff_cookbook.html （JAX autodiff cookbook 讨论非光滑函数）
- **根因分析**: 自动微分要求函数可微，非光滑点处导数不存在。

### 4.4 simphony 无 JAX 集成
- **问题描述**: simphony 虽然可选依赖 JAX，但其核心子网络增长算法使用纯 numpy，无法利用 JAX 的自动微分、JIT 编译和 GPU 加速。
- **影响**: 大规模电路仿真慢，无法进行梯度优化。
- **来源 URL**: https://simphonyphotonics.readthedocs.io/en/stable/index.html （文档提到 JAX 但核心算法未使用）
- **根因分析**: simphony 的设计早于 JAX 普及，核心算法未重构。

### 4.5 PoLaRIS 现有实现无 JAX 支持
- **问题描述**: PoLaRIS 的 `SDict = dict[tuple[str, str], np.ndarray]` 使用 numpy，所有模型函数（`waveguide_s`、`ring_resonator_s` 等）使用 `np.asarray`、`np.exp` 等 numpy 函数，无法被 JAX 追踪。
- **影响**: 无法进行梯度优化、JIT 编译、GPU 加速。
- **来源 URL**: `/workspace/src/polaris/sim/types.py`（第 18 行）；`/workspace/src/polaris/sim/models.py`（所有模型函数）
- **根因分析**: 历史实现选择 numpy 以降低依赖，但牺牲了 JAX 能力。

### 6.2 改进点

1. **双后端支持**: 保持 numpy 后端（CPU 兼容）和 JAX 后端（自动微分、JIT、GPU），通过 `backend` 参数切换。这不是 fall-back，而是显式后端选择。
2. **JIT 编译**: 对 `simulate()` 方法增加 `jit=True` 选项，使用 `jax.jit` 编译。
3. **自动微分**: 增加 `grad_simulate()` 方法，使用 `jax.grad` 计算参数梯度。
4. **GPU 加速**: JAX 自动支持 GPU，无需额外代码。
5. **蒙特卡洛分析**: 增加 `monte_carlo()` 方法，使用 `jax.vmap` 并行计算多个参数变体。

### 6.3 创新点（标注"创新"）

1. **创新：双后端无缝切换** — PoLaRIS 同时支持 numpy 和 JAX 后端，通过 `backend` 参数切换。sax 强制依赖 JAX，PoLaRIS 在无 JAX 环境下仍可工作（numpy 后端）。
   - **创新逻辑**: 通过抽象数组接口（`ArrayLike`），统一 numpy 和 jax.numpy 的 API 调用。
   - **支持理论**: JAX 设计为 numpy 兼容（`jax.numpy` 模仿 `numpy` API）。
   - **案例**: 在无 GPU 的 CI 环境用 numpy 后端，在有 GPU 的工作站用 JAX 后端，代码无需修改。

2. **创新：AOT（Ahead-of-Time）编译** — PoLaRIS 支持 AOT 编译，预先编译电路仿真函数，避免 JIT 的首次开销。sax 仅支持 JIT。
   - **创新逻辑**: 使用 `jax.jit(f).lower(...).compile()` 预编译，缓存编译结果。
   - **支持理论**: JAX 的 AOT 编译 API。
   - **案例**: 生产环境部署时预编译，首次调用无开销。

3. **创新：混合精度仿真** — PoLaRIS 支持 float32/float64 混合精度，float32 用于快速优化迭代，float64 用于高精度验证。sax 仅支持 float64（JAX 默认）。
   - **创新逻辑**: 通过 `jax.config.update("jax_enable_x64", True/False)` 切换精度。
   - **支持理论**: IEEE 754 浮点标准；数值分析理论。
   - **案例**: 优化初期用 float32 快速探索，收敛后用 float64 精细优化，总时间减少 50%。

4. **创新：可微分 PDK 模型** — PoLaRIS 的 PDK 模型（`src/polaris/pdk/`）支持自动微分，用户可直接对工艺参数（如波导宽度、厚度）求导。sax 的模型需用户自行实现 JAX 版本。
   - **创新逻辑**: PDK 模型使用 JAX 实现，支持工艺参数到 S 参数的端到端求导。
   - **支持理论**: JAX 自动微分；光子器件模型理论。
   - **案例**: 对波导宽度求导，优化良率敏感度。
