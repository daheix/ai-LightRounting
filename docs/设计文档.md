## 1. 项目定位

PoLaRIS（光弈）是开源光电子 AI 智能布局布线引擎，提供从网表到 GDS 的端到端自动化流水线。

**核心定位**:
- 光子 EDA 全流程覆盖（PDK → 布局 → 布线 → 仿真 → DRC/LVS → GDS 导出）
- AI 强化学习布局布线（对标 Google AlphaChip）
- 多物理场仿真（FDTD/FDE/EME/BPM/FDFD + 多物理场耦合）
- 量子光子电路（玻色采样/KLM/QKD/QEC）
- 纯 CPU 实现（R04 战略：不参与 GPU 计算）

**工艺平台**: SOI / SiN / InP / LNOI 四大平台，36 器件全溯源

### 2.2 数据流

```
输入: circuit.json (网表)
  │
  ├─1─▶ polaris_core.make_circuit() → CircuitSpec (器件+连接+画布)
  │
  ├─2─▶ polaris_place.place_circuit() → 布局结果
  │     │  模式: analytical (DREAMPlace) / ppo_gnn (AlphaChip)
  │     ▼
  ├─3─▶ polaris_route.route_circuit() → 布线结果
  │     │  CurvyRouter (曲线波导) + router_advanced (17 种高级算法)
  │     ▼
  ├─4─▶ polaris_circuit.CircuitSimulator → S 参数仿真
  │     │  cascade_circuit() (Filipsson 1978 子网络增长)
  │     │  sax 交叉验证误差 < 1e-15（R3 验收达标）
  │     ▼
  ├─5─▶ polaris_drc.run_drc() + polaris_lvs.run_lvs() → 验证
  │
  ├─6─▶ polaris_gdsio.export_gds() → GDSII 导出
  │
  └─7─▶ 输出: GDS + 报告 + 训练数据

orchestrator.run_eda_flow() 一键执行 9 stage:
  parse → place → route → sim → drc → lvs → parasitic → yield → export
```

## 4. 核心设计模式

### 4.1 IPO 三段式文档化

每个子模块遵循 **Input → Process → Output** 单一职责设计：
- **Input**: 明确函数入参（类型/默认值/物理含义）
- **Process**: 明确算法/公式/文献溯源（R02 学术诚信）
- **Output**: 明确返回 dict 字段（JSON-serializable）

每个 `__init__.py` 顶部 docstring 含 IPO 段落，失败即 raise（R03 禁止 fall-back）。

### 4.2 monorepo 独立管理

每个子模块可独立：
- `pip install -e modules/<name>/`（独立安装）
- `pytest modules/<name>/tests/`（独立测试）
- 修改不影响其他子模块（独立升级）

### 4.3 C ABI 公共层

`modules/_c_abi/`:
- `polaris_types.h`: 统一类型（`polaris_circuit_t`/`polaris_device_spec_t`/`polaris_tensor_t`/`polaris_placement_result_t`/`polaris_routing_result_t`/`polaris_result_t`/`polaris_error_t`）
- `polaris_error.h`: 统一错误处理（`POLARIS_OK`=0 / `POLARIS_ERR_INVALID` / `POLARIS_ERR_NOTFOUND` / ...）

Python ↔ C 函数一一对应，函数名 `polaris_<module>_<verb>_<noun>`，纯数据结构跨语言传递，统一错误码。

### 4.4 仿真回馈闭环（SimLoop）

```
布局 → 布线 → S参数仿真 → 损耗评估 → 约束检查 → 反馈
  ↑                                              │
  └──────────────── 反馈调整布局/布线参数 ─────────┘
```

- `CircuitSimulator.simulate()` 调用 `cascade_circuit()` 级联 S 参数
- `ConstraintChecker.check()` 检查损耗/弯曲半径/间距/交叉数
- `FeedbackAdapter.adapt()` 将仿真违规转化为布局调整建议

### 4.5 训练方法论

**训练数据**:
| 阶段 | 数据 | 规模 | 用途 |
|------|------|------|------|
| 预训练 | GDSFactory 38 电路 | 38 | 基础布局策略 |
| 强化训练 | LiDAR 9 + PICBench 24 | 33 | 大规模布局布线 |
| 变体增强 | 参数扫描+扰动+缩放 | 1000+ | 数据增强 |
| 校准验证 | 标准成品布局 | 71 | 仿真校准 |

**奖励函数**:
```
total_reward = (
    + 0.30 * port_alignment_reward     # 端口对齐
    + 0.25 * wirelength_reward          # cosWA 弯曲感知线长
    + 0.20 * congestion_reward          # CNN 拥塞预测
    - 0.15 * bend_violation_penalty     # 弯曲半径违反
    - 0.10 * crossing_penalty           # 波导交叉
    - 0.10 * thermal_penalty            # 热串扰
    + sim_feedback_bonus                # 仿真回馈
    - sim_loss_penalty                  # 仿真损耗
)
```

## 7. 关键技术决策

| 决策点 | 方案 | 理由 |
|--------|------|------|
| 架构 | v5.0 monorepo 33 子模块 | 独立管理/独立测试/独立升级 |
