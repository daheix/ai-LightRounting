# R11 V8 极简工作流（强制）

**直接在 main 分支开发，不切换，不备份。** 本规则替代 R06/R08。

---

## 1. 分支

- 只用 `main`，禁止 dev/feature/worktree
- 启动时检查：`git branch --show-current`（必须在 main）
- **禁止 force push main**（R382 v2.0，2026-07-06）
  - force push 会覆盖远程历史，原 commit 成为孤儿对象经 GC 后永久丢失
  - R382 v1.1 曾基于错误诊断声称"main 被 squash+force push"，v2.0 已撤销该诊断（实际 main 有 2012 个完整 commit）
  - 但 force push 禁令本身仍是通用 git 最佳实践，保留
  - 正确做法：每个小任务单独 `git commit` + `git push`，保留完整可溯源链
- **clone 后必须 fetch 所有远程分支**（R382 v2.0，2026-07-06）
  - `git clone` 默认只 fetch main（`remote.origin.fetch = +refs/heads/main:refs/remotes/origin/main`），其他分支（如 `trae/agent-*`）不可见
  - clone 后执行：`git fetch origin 'refs/heads/*:refs/remotes/origin/*'`
  - 验证：`git branch -a` 应显示所有远程分支
  - 历史 tag 验证：`git tag -l` 应包含 `r1-r378-history-backup`（R1-R378 完整历史备份）

## 2. 提交

每个小任务完成后立即执行：
```
git add <精确文件名>   # 禁止 git add -A
git commit -m "<type>: <简述>"
git push origin main   # 禁止 --force
```

- 无变更时不创建空提交
- auto_commit V8 每 6 分钟自动兜底提交
- **禁止 `git push --force` / `git push --force-with-lease`**（R382 v2.0 保留）
- ⚠️ **建议避免 `git merge --squash` / `git rebase -i` 压缩 commit**（R382 v2.0 降级为建议，非强制；squash merge 在某些场景合理，但会丢失独立 commit 历史，操作记录中的 hash 不可溯源）
- commit message 类型必须与内容一致（代码变更用 `fix:`/`feat:`，文档用 `docs:`，禁止 `docs:` 标注含代码变更的 commit）

## 3. 任务派发前核查（防止重复造轮子）

**必须依次执行**：
```bash
git log --all --oneline --follow -- <文件>  # 查 git 历史
grep <功能名> 操作记录.md                     # 查操作记录
ls <目标路径>                               # 查现有文件
```

| 核查结果 | 行动 |
|---------|------|
| git 有 commit + 操作记录有 | 跳过，禁止重复实现 |
| git 无 + 操作记录无 | 可以派发 |
| 目标文件存在 | 必须 Read 后再决定 |

## 4. 操作记录

每个小任务完成后 **5 分钟内**追加到 `操作记录.md`，包含：
- 轮次编号、交付文件、测试结果（精确数字）
- 规则依据、无 fall-back 声明
- **禁止**模糊描述

## 5. 监控脚本

| 脚本 | 轮询 | 功能 |
|------|------|------|
| `scripts/auto_commit.py V8` | 6 分钟 | 检测变更→提交→push |
| `scripts/keepalive.sh` | 5 分钟 touch | 保活防超时 |

守护进程 crash → 立即重启并记录。

## 6. 会话恢复

每次会话启动检查：
```bash
git branch --show-current   # 必须在 main
ps aux | grep auto_commit   # 守护进程在运行
ps aux | grep keepalive    # 保活在运行
```

## 7. 磁盘空间

日志上限 99MB（RotatingFileHandler，单文件 99MB × 2 备份 = 198MB 总上限）。空间不足时删除：swiftly(6.5G)/mise(3.0G)/rustup(1.8G)。

**禁止使用 Git LFS**（2026-07-06 用户指示）：
- 禁止 `git lfs install` / `.gitattributes` 配置 LFS filter
- 禁止 `git lfs track` 任何文件类型
- 大文件（<100MB）直接 git add 提交，不使用 LFS
- 单文件硬上限 99MB（低于 GitHub 100MB 硬限制，安全余量 1MB）

## 8. Bug 处理

发现即修，附回归测试，禁止 TODO/FIXME/HACK 残留。

## 9. 违规

| 违规 | 处理 |
|------|------|
| 不核查就派发任务 | 立即停止，重新核查 |
| git add -A | 拒绝 |
| --force push | 拒绝并告警 |
| 不刷新操作记录 | 禁止派发新任务 |
