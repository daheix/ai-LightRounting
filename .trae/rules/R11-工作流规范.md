# R11-工作流规范（V8 极简模式，强制）

> 本规则于 2026-06-28 根据用户批评制定，用于替代 R06 分支纪律和 R08 代码提交纪律中过于复杂的部分。
> **核心原则：直接在 main 分支开发，直接提交 main 分支，不搞备份，不搞分支切换。**

---

## 1. 分支管理（V8 简化版）

### 1.1 只用 main 分支
- 仓库只有 `main` 一个长期分支
- 禁止创建/使用 dev/feature/backup 等临时分支
- 禁止 `git worktree`
- 禁止 `git merge` 合并其他分支到 main（除非 R06 特殊说明）

### 1.2 分支检查
每次会话启动必须检查：
```bash
git branch --show-current  # 必须在 main
git fetch --all --prune    # 拉取最新
git status                # 无未提交变更（除非正在开发）
```

---

## 2. 代码提交（每个小任务完成后立即提交）

### 2.1 提交流程（严格顺序）
```
1. git add <精确文件名>          # 禁止 git add -A / git add .
2. git commit -m "<type>: <简述>"
3. git push origin main          # 禁止 --force / --force-with-lease
```

### 2.2 提交信息规范
- `<type>` 必须是：feat / fix / docs / refactor / test / chore
- 简述：不超过 50 字，说明"做了什么"，不是"为什么"
- 必须在提交信息末尾注明规则依据

### 2.3 自动提交守护（V8）
- `scripts/auto_commit.py V8` 每 6 分钟自动检测并提交
- 兜底机制：主线程忘记提交时，守护进程会自动补提交
- 守护进程失败（守护进程本身 crash）则告警，不静默

### 2.4 空提交禁止
无变更时不创建空提交，等待下次有变更时再提交。

---

## 3. 任务派发前必须核查（防止重复造轮子）

### 3.1 核查流程（每个任务派发前必须执行）
在任何 subagent 被派发实现一个功能前，**必须依次执行**以下三项核查：

```bash
# 步骤 1：核查 git 全历史（所有分支）
git log --all --oneline --follow -- '<目标文件路径>'

# 步骤 2：核查操作记录.md
grep '<功能关键词>' 操作记录.md

# 步骤 3：检查目标路径是否已有文件
ls -la <目标文件路径>  # 如果存在，必须先 Read 确认内容
```

### 3.2 核查判断规则
| 核查结果 | 行动 |
|---------|------|
| git 历史有 commit + 操作记录有记录 | **跳过**，该功能已完成，禁止重复实现 |
| git 历史有 commit + 操作记录无记录 | **核查**：判断是历史实现还是被删除的功能 |
| git 历史无 commit + 操作记录无记录 | **可以派发**，首次实现 |
| 目标文件已存在但无 git 历史 | **必须先 Read**，确认内容后再决定 |

### 3.3 禁止的行为
- 禁止不核查就直接 Write 创建文件（即使文件名不同也可能重复实现）
- 禁止用 "先创建再说" 绕过核查
- 禁止用新文件名绕过"已有同名功能"的判断

## 4. 操作记录实时刷新（R07 强化版）

### 4.1 实时追加规则
每个小任务完成后的 **5 分钟内**，必须追加一条操作记录到 `操作记录.md`：

```
## 轮次 N+X：<任务名>（YYYY-MM-DD HH:MM）

### 路标编号
<对应的 spec 或路标编号>

### 核查过程
- git 历史核查：<结果>
- 操作记录核查：<结果>
- 目标文件检查：<结果>

### 执行结果
<任务的具体执行结果，数字要精确>

### 测试结果
<测试通过数 / 总数>

### 规则依据
<引用的规则编号>

### Git 提交
- commit `<hash>`：<提交信息>
- <其他变更>
```

### 4.2 操作记录内容要求
- 必须记录**实际数字**（通过数/行数/commit hash），不能模糊描述
- 必须记录**核查过程**（git 历史 + 操作记录），不能跳过
- 必须记录**无 fall-back 声明**（如果业务失败，记录并告警，不是静默）

### 4.3 历史记录保留
- 操作记录是历史，不删除
- 每次追加是追加，不是覆盖
- 错误的记录用删除线标注，不抹除（保留追查线索）

## 5. 监控脚本管理

### 5.1 V8 守护进程
| 脚本 | 轮询间隔 | 功能 |
|------|---------|------|
| `scripts/auto_commit.py V8` | 6 分钟 | 检测变更 → git add 精确文件 → commit → push |
| `scripts/keepalive.sh` | 5 分钟 touch / 17 分钟消息 | 保活防超时 |

### 5.2 脚本变更规范
- 修改 `auto_commit.py` 视为高风险操作，必须追加操作记录
- 升级版本号必须体现在文件名或文件头注释（如 V7→V8）
- 删除脚本必须先确认无守护进程在使用

### 5.3 禁用脚本处理
- 禁用的脚本重命名为 `.disabled`，不删除（保留历史）
- 永久不用的脚本单独目录管理（如 `scripts/retired/`）

## 6. 会话恢复机制

### 6.1 每次会话启动检查清单
```
1. git branch --show-current  # 必须在 main
2. git log --oneline -3     # 确认最新 commit 是自己的
3. git status               # 检查工作区状态
4. ps aux | grep auto_commit # 确认守护进程运行
5. ps aux | grep keepalive  # 确认保活脚本运行
6. tail -3 操作记录.md      # 确认最后一条记录的时间
```

### 6.2 守护进程恢复
如果守护进程不在运行，立即重启：
```bash
nohup python3 scripts/auto_commit.py > /tmp/auto_commit_stdout.log 2>&1 &
nohup bash scripts/keepalive.sh > /dev/null 2>&1 &
```

### 6.3 会话中断恢复
会话中断后重新连接时：
1. 检查最后 commit 是否已 push 到远端
2. 检查操作记录最后一条是否已提交
3. 如果有未提交的变更，继续完成后再派发新任务

## 7. 磁盘空间管理

### 7.1 循环日志
- `auto_commit.py`：日志上限 10MB（RotatingFileHandler，1 个备份）
- `keepalive.sh`：日志在 `/tmp/keepalive.log`，定期清理或截断
- `polaris` 应用日志：使用 `scripts/logging_config.py` 的 RotatingFileHandler

### 7.2 磁盘告警
如果磁盘剩余空间 < 5GB，必须：
1. 清理 `/tmp/` 下的临时文件
2. 清理 `auto_commit.log`（循环日志自动管理）
3. 检查 `3dtool/` 目录大小，如果 3dtool 子仓库 > 10GB，考虑重新打包分片上传

---

## 8. Bug 处理（R05 强化版）

### 8.1 发现即修
- 发现 Bug 立即修复，禁止遗留
- 禁止 `TODO` / `FIXME` / `HACK` 残留到提交
- 修复后必须附回归测试

### 8.2 Bug 记录格式
```
### Bug 修复记录
**Bug**：<问题描述>
**根因**：<分析得出的根本原因>
**修复**：<具体修复方式>
**回归测试**：<防止复发的测试用例>
```

---

## 9. 违规处理

| 违规行为 | 处理方式 |
|---------|---------|
| 不核查 git 历史就派发任务 | 立即停止，回退本次实现，重新核查 |
| 使用 `git add -A` / `git add .` | 拒绝合并，要求精确文件名 |
| 使用 `--force` push | 拒绝并告警 |
| 不刷新操作记录 | 禁止派发新任务，先补记录 |
| 删除操作记录内容 | 严重警告，恢复后继续 |
| 守护进程 crash 不告警 | 立即修复并记录 |

## 10. 与其他规则的关系

| 规则 | 与 R11 的关系 |
|------|--------------|
| R06 分支纪律 | **被 R11 替代**：V8 模式只用 main 分支，R06 的 dev 分支规则不再适用 |
| R08 代码提交 | **被 R11 强化**：R08 的每 20 分钟提交改为每个小任务完成后立即提交 |
| R07 操作记录 | **被 R11 强化**：R07 要求追加，R11 要求实时（5 分钟内）追加 + 核查过程 |
| R03 禁止 fall-back | **被 R11 保留**：R11 无额外修改 |
| R05 Bug 必修 | **被 R11 强化**：R11 要求记录根因和回归测试 |
| R09 权威检索 | **被 R11 保留**：V8 模式不改变 R09 的检索要求 |
