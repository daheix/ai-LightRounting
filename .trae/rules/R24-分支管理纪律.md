# 规则 R24：分支管理纪律（强制，禁止孤儿分支）

## 24.1 核心原则：禁止孤儿分支

- **禁止孤儿分支**：仓库中不得存在未被合并到 `main` 的游离开发分支（孤儿分支）。
- 所有开发分支必须最终合并到 `main`，合并后立即删除开发分支，禁止残留。
- 仓库**只允许保留两个长期分支**：
  - `main`：稳定发布分支，始终可编译可测试
  - `dev`：开发集成分支，所有开发工作在此进行
- 临时开发分支（如 `trae/agent-xxx`、`feature/xxx`、`fix/xxx`）在合并到 `dev`/`main` 后必须立即删除（本地 + 远端）。

## 24.2 分支生命周期

1. **创建**：从 `dev` 创建临时分支开发
2. **合并**：开发完成后合并到 `dev`，再由 `dev` 合并到 `main`
3. **删除**：合并完成后立即删除临时分支（`git branch -d <branch>` + `git push origin --delete <branch>`）
4. **同步**：`main` 和 `dev` 必须保持同步，`dev` 不得落后 `main` 超过 1 个提交

## 24.3 强制清理

- 每次会话启动时必须检查分支状态：`git fetch --all --prune && git branch -a`
- 发现孤儿分支（未合并到 main 的远端分支）必须立即合并或删除
- 禁止 `git reset --hard` 到其他分支导致 main 丢失提交（除非 main 是旧的、其他分支包含最新代码）

## 24.4 禁止行为

- **禁止** 保留超过 2 个长期分支（main + dev）
- **禁止** 创建 `develop`、`trae/auto-commit`、`trae/solo-agent-xxx` 等冗余分支
- **禁止** 远端存在已合并但未删除的分支
- **禁止** 在 main 上直接开发（必须通过 dev 或临时分支）
