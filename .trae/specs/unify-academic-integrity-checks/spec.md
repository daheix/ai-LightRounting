# 学术诚信检查统一管理 Spec

## Why

PoLaRIS 项目当前存在 **4 个分散的学术审核文档**，内容重叠且版本混乱：
1. `/workspace/20260627-mvp技术诚信学术审核.md`（2026-06-28，MVP 全量审核）
2. `/workspace/docs/academic_integrity_audit.md`（v1.0 + v2.0 章节，2026-06-24~28）
3. `/workspace/docs/academic_integrity_audit_v2.md`（v2.0，2026-06-27，43 聚类模块）
4. `/workspace/docs/devplan_audit_report.md`（开发计划审核）

用户要求：把多个学术审核文档**全部梳理**，统一到一份最新文档统一管理；扩展为**整个项目的学术审查**（不只是今天刚完成的），覆盖代码合理性、100% 完成度、代码与设计匹配性；按**模块/文件夹/文件**方式统一整理；文件改名为 **`学术诚信检查.md`**；用**版本号**记录每次检查发现的 bug 和数据；最新内容放**文件开头**，后面是每个文件、每个算法、每个公式的学术诚信；**禁止造假**。

## What Changes

- **新建统一文档** `/workspace/docs/学术诚信检查.md`（中文文件名，按用户要求）
- 文档结构：版本日志（最新在前）→ 项目总览 → 按子包/文件/算法/公式的逐项学术诚信清单
- **合并** 4 个分散文档的关键发现到新文档（保留历史版本日志）
- **全项目逐子包审查** 22 个子包 / 357 文件 / 120,692 行代码
- 审查维度：① 文献引用真实性 ② 公式/参数可溯源性 ③ 代码合理性 ④ 完成度 ⑤ 代码-设计匹配性 ⑥ R03 禁止 fall-back ⑦ R05 Bug 残留
- **每次检查标记版本号**（v3.0 / v3.1 ...），记录该次发现的 bug 数、修复数、数据修正
- **归档** 旧文档：保留但不主动维护（避免数据丢失）
- **删除** 重复或无用的中间文档（如有）
- 修复审查中发现的 bug（同步到代码 + 文档）
- 全部记录到操作记录.md

**BREAKING**: 学术审核文档统一为 `docs/学术诚信检查.md`，旧文档 `academic_integrity_audit.md` / `academic_integrity_audit_v2.md` / `20260627-mvp技术诚信学术审核.md` 不再维护（保留为历史归档）。

## Impact

- Affected specs: `audit-academic-integrity-deep` / `audit-mvp-academic-integrity-20260627`（历史，归档）
- Affected code: `src/polaris/` 全部 22 子包 357 文件 120,692 行
- Affected docs: 4 个旧学术审核文档（归档） + 新建 `docs/学术诚信检查.md`
- 关联规则: R02 学术诚信 / R03 禁止 fall-back / R05 Bug 必修 / R07 操作记录

## ADDED Requirements

### Requirement: 统一学术诚信检查文档

系统 SHALL 新建 `/workspace/docs/学术诚信检查.md` 作为唯一权威学术诚信检查文档，结构如下：
1. **文件头**：文档说明 + 当前版本号 + 最后更新日期
2. **§1 版本日志**（最新在前）：每次检查的版本号 / 日期 / 范围 / 发现 bug 数 / 修复数 / 数据修正 / 审查员
3. **§2 项目总览**：子包数 / 文件数 / 代码行数 / 22 子包统计表
4. **§3 按子包逐项审查**：每个子包一节，含文件清单 + 算法清单 + 公式清单 + 审查结论
5. **§4 关键算法与公式溯源**：跨子包的核心算法（FDTD/EME/FDE/RCWA/BPM/PPO/GAE/KLM/BB84 等）逐条溯源
6. **§5 Bug 与修复历史**：所有历史 bug 按版本号归档
7. **§6 学术诚信声明**：R02/R03/R05 合规声明

#### Scenario: 版本日志记录
- **WHEN** 完成一次新的学术检查
- **THEN** 在 §1 顶部追加新版本条目，含版本号、日期、范围、发现 bug 数、修复数、数据修正清单

#### Scenario: 按子包结构化
- **WHEN** 审查某个子包（如 sim/）
- **THEN** 在 §3 下新建该子包小节，含：文件清单（含行数）、算法清单、公式清单、文献引用清单、Bug 清单、审查结论

### Requirement: 全项目逐子包审查

系统 SHALL 对 22 个子包逐个审查，每个子包输出：
- 文件清单（文件名 / 行数 / 主要功能）
- 算法清单（算法名 / 实现位置 / 来源文献 / 一致性）
- 公式清单（公式 / 参数 / 来源 / 一致性）
- 文献引用清单（URL / 作者 / 年份 / 可达性）
- Bug 清单（描述 / 根因 / 修复 / 验证）
- 完成度评估（100% / 部分 / 未完成）
- 代码-设计匹配性（一致 / 分歧 / 待核查）

#### Scenario: 子包审查
- **WHEN** 审查子包 `sim/fdtd/`
- **THEN** 记录 Yee 网格 / CPML / TFSF / 色散介质 / 子像素平滑 等算法的文献溯源与实现一致性

### Requirement: 版本号管理

系统 SHALL 用版本号管理每次检查：
- v3.0 = 首次统一文档建立（合并 4 个旧文档 + 全项目审查）
- v3.1, v3.2 ... = 后续每次检查递增
- 每个版本记录：发现 bug 数 / 修复数 / 数据修正 / 审查员 / 日期

#### Scenario: 版本递增
- **WHEN** 用户发起一次新的学术检查
- **THEN** 版本号 +0.1，在 §1 顶部追加新条目

### Requirement: 旧文档归档

系统 SHALL 保留 4 个旧学术审核文档作为历史归档，但在文件头标注 "已归档，最新内容见 docs/学术诚信检查.md"：
- `/workspace/20260627-mvp技术诚信学术审核.md`
- `/workspace/docs/academic_integrity_audit.md`
- `/workspace/docs/academic_integrity_audit_v2.md`
- `/workspace/docs/devplan_audit_report.md`

#### Scenario: 旧文档归档
- **WHEN** 新文档建立完成
- **THEN** 在 4 个旧文档顶部追加归档声明，指向新文档

## MODIFIED Requirements

### Requirement: 学术诚信审查（原有）

原有审查仅针对 M4-M6 或 MVP 单次审查，现扩展为**全项目持续审查**，按子包/文件/算法/公式结构化组织，支持版本号持续刷新。

## REMOVED Requirements

无（不删除任何文档，仅归档）
