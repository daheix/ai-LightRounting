## §1 迭代框架

### 1.1 每次迭代从0开始原则

**含义**: 每一轮迭代不依赖前一轮的"已知问题列表"，而是：
1. 重新扫描所有源码文件（AST 解析 + 文本搜索）
2. 对每个模块从物理公式、算法实现、数据流、API 契约、边界条件五个维度独立核查
3. 前轮记录仅作为"已知覆盖区域"参考，避免重复，不作为跳过理由

**五个核查维度**:
- **D1 物理公式**: 所有常数/公式与文献逐行比对，数值误差 ≤ 机器精度
- **D2 算法实现**: 伪代码 vs 实际代码一致性，循环/递归终止条件
- **D3 数据流**: 输入校验 → 处理 → 输出边界，无静默丢失
- **D4 API 契约**: 参数类型/范围/副作用文档一致性
- **D5 边界条件**: 空输入/零除/溢出/NaN/Inf/类型转换/编码边界

### 1.3 禁止行为

- 禁止跳过"已知无问题"的区域（必须重新扫描）
- 禁止基于前轮"无发现"减少本轮覆盖范围
- 禁止添加假数据/fall-back 让程序"看起来正常"
- 禁止文献引用二手/无 URL/不可达的资源
- 禁止降低测试标准（每轮必须有具体量化验证）

## §2 发现问题处理规范

### 2.1 问题分级

| 级别 | 定义 | 处理要求 | 记录格式 |
|------|------|----------|----------|
| **P0** | 假实现/完全不工作/数据静默丢失/违反复式 | **立即修复**，附回归测试，24h 内推送 | R{N}-P0-N |
| **P1** | 算法错误/性能严重不达标/R03 fall-back | **当日修复**，附回归测试 | R{N}-P1-N |
| **P2** | 文献溯源不足/参数精度不够/文档不符 | **本轮内修复** | R{N}-P2-N |
| **P3** | 代码风格/注释不足/命名不规范 | 记录但不阻塞，纳入下一轮 | R{N}-P3-N |

### 2.2 修复验证要求

每个修复必须满足：
1. **代码修复** + **单元测试** + **集成测试**（如有对应模块）
2. 测试通过后才能提交（禁止带病推送）
3. 操作记录.md 记录：轮次/编号/模块/问题/根因/修复/文献/测试结果

### 2.3 无 Bug 发现声明

若某轮扫描未发现问题，必须明确声明：
```
R{N} 扫描结论: [子包] 未发现 P0/P1/P2 问题。
已核查: [文件列表] / 维度: D1-D5 / 方法: [AST/文本/动态测试]
```

## §6 工具与环境

### 6.1 核心工具

- AST 解析: `ast.parse` + `ast.walk`
- 文本搜索: `grep` / `rg`
- 测试运行: `pytest`
- 覆盖率: `pytest --cov=polaris --cov-report=term-missing`
- 复杂度: `radon cc -a src/polaris`
- 文献核查: `WebSearch` + 官方文档 URL 验证

### 6.2 600 秒汇报脚本

```bash
# scripts/round_progress_hook.sh — 每 600 秒前台汇报
#!/bin/bash
INTERVAL=600
LOG=/tmp/round_progress.log
while true; do
    echo "══════════════════════════════════════════════════════════"
    echo "  Rounds Progress Report — $(date '+%Y-%m-%d %H:%M:%S')"
    echo "══════════════════════════════════════════════════════════"
    if [ -f /tmp/current_round ]; then
        echo "当前轮次: $(cat /tmp/current_round)"
    fi
    if [ -f /tmp/round_p0_count ]; then
        echo "P0 发现数: $(cat /tmp/r0_count 2>/dev/null || echo 0)"
    fi
    echo "══════════════════════════════════════════════════════════"
    sleep $INTERVAL
done
```
