## 2. 物理模型与数学基础（DAG / 图论 / 拓扑排序）

网表在物理层描述光电子电路的拓扑结构：器件实例为图的顶点，端口连接为图的边。网表解析的本质是把人类可读文本（YAML/JSON/SPICE）映射为有向无环图（DAG）或多重无向图，再经拓扑排序与子电路展开，归约为可仿真的网络。

### 2.1 网表到图的映射

设网表 $N = (I, C, P)$，其中 $I$ 为器件实例集合，$C$ 为端口连接集合，$P$ 为外部端口集合。构建有向二分图 $G = (V, E)$：

- 顶点 $V = I \cup P_{\text{ext}}$（实例节点 + 外部端口节点）；
- 有向边 $E = \{(u.\text{port}_i \to v.\text{port}_j) \mid (u, p_i, v, p_j) \in C\}$。

无环性约束：物理 PIC 的连接关系通常无反馈（反馈由 S 参数级联在频域处理），故 $G$ 应满足 DAG 条件；若解析出现环，则告警退出（规则 14，禁止 fall-back）。

### 2.2 拓扑排序的必要性

子电路展开、层次化布局布线、增量仿真缓存（C02 §8.1）均要求按依赖顺序处理器件。拓扑排序保证：父器件先于子器件被处理，子电路实例先于上层电路被展平。

## 3. 控制方程（邻接矩阵、连接度）

### 3.1 邻接矩阵表示

对 $|V| = n$ 的图 $G$，邻接矩阵 $\mathbf{A} \in \{0,1\}^{n \times n}$ 定义为：

$$
A_{ij} = \begin{cases} 1, & \text{若存在边 } v_i \to v_j \\ 0, & \text{否则} \end{cases}
$$

### 3.2 度与连接度

顶点 $v_i$ 的入度（in-degree）与出度（out-degree）：

$$
\deg_{\text{in}}(v_i) = \sum_{j=1}^{n} A_{ji}, \quad \deg_{\text{out}}(v_i) = \sum_{j=1}^{n} A_{ij}
$$

PIC 中典型器件（直波导、MMI、环谐振器）的端口数为 2–4，故 $\deg_{\text{in}}, \deg_{\text{out}} \in [0, 4]$，矩阵 $\mathbf{A}$ 高度稀疏，PoLaRIS 采用邻接表（`networkx.MultiDiGraph`）存储，空间复杂度 $O(n + m)$（$m = |E|$）。

### 3.3 连通分量

无向版本 $G^T = (V, E^T)$（边方向忽略）的连通分量对应独立子电路，可并行求解。识别算法为 BFS/DFS，复杂度 $O(n + m)$（C02 §3.2 已实现）。

## 4. 离散化方法（语法解析 AST、token 化）

网表解析在「文本 → 内存对象」层面属于语法分析问题，离散化即把字符流切分为 token 流再构造抽象语法树（AST）。

### 4.1 YAML/JSON 网表的 token 化

YAML 1.2.1（Ben-Kiki 等 2009）规范定义了三类节点：mapping（dict）、sequence（list）、scalar（str/num/bool）。PoLaRIS 用 PyYAML `safe_load` 完成词法+语法分析得到 Python 字典，再按 PoLaRIS schema 构造 AST：`raw_dict = yaml.safe_load(text)` → 遍历 `raw_dict["instances"]` 调用 `_parse_instance`，遍历 `raw_dict["connections"]` 调用 `_parse_connection`。JSON 网表（SiEPIC 格式）走 `json.loads`，schema 由 `siepic_netlist.py:133` `parse_siepic_json` 定义。

### 4.2 SPICE 网表的 token 化（PoLaRIS 写出方向）

PoLaRIS 的 SPICE 网表生成（`sim/mna_spice.py:102`）按 SPICE3 语法定义 token：行首字符决定器件类型（`R/C/L/V/I/X`），`.subckt/.ends` 标记子电路边界，节点名为整数或字符串。词法分析按行分割 + 空白切分即可，无需复杂 lexer。

### 4.3 AST 节点定义

PoLaRIS 采用 dataclass 直接表达 AST 节点（规则 14：禁止假数据，禁止 fall-back 实现）：

- `NetlistInstance`：实例 ID + 组件名 + 平台 + settings；
- `NetlistConnection`：源/目的实例 + 源/目的端口 + 约束字典；
- `Netlist`：实例列表 + 连接列表 + 名称。

## 5. 边界条件（端口类型约束、子电路边界）

### 5.1 端口方向约束

光子器件端口具有方向性（输入/输出/双向）。PoLaRIS `Port` 类（`pdk/port.py`）记录 `direction`（E/W/N/S）与 `waveguide_type`（strip/rib/slot）。连接合法性校验：

- 同种 `waveguide_type` 才可连接（模式匹配）；
- 端口方向应使光从源端口指向目的端口；
- 模式宽度需匹配（容差由约束字典给定）。

校验失败即 `raise ValueError`，禁止 fall-back 跳过（规则 14）。

### 5.2 子电路边界

子电路（`.subckt`）的端口在展开时映射为「外部端口」，内部节点重命名为唯一标识（`{sub_name}_{node}`）以避免命名冲突。展开后，子电路的内部连接被合并入父电路的连接列表，外部端口成为父电路的端口节点。

### 5.3 接地/参考节点

SPICE 网表要求所有节点存在到节点 0（地）的直流路径；光子网表无此约束（光波无接地概念），但需指定「光学参考面」即外部端口集合 $P_{\text{ext}}$，用于 S 参数级联的边界条件。

### 6.4 子电路展开

```
function expand_subcircuits(net, sub_defs):
    expanded_insts ← []
    expanded_conns ← []
    for inst in net.instances:
        if inst.component in sub_defs:
            sub_net ← sub_defs[inst.component]
            for sub_inst in sub_net.instances:
                expanded_insts.append(rename(sub_inst, prefix=inst.instance_id))
            for sub_conn in sub_net.connections:
                expanded_conns.append(redirect(sub_conn, prefix=inst.instance_id))
        else:
            expanded_insts.append(inst)
    return Netlist(expanded_insts, expanded_conns + net.connections, net.name)
```

### 6.5 拓扑排序（Kahn 算法）

```
function topological_sort_kahn(G):
    in_degree ← {v: 0 for v in G.V}
    for (u, v) in G.E:
        in_degree[v] += 1
    queue ← deque([v for v in G.V if in_degree[v] == 0])
    order ← []
    while queue not empty:
        u ← queue.popleft()
        order.append(u)
        for v in G.neighbors(u):
            in_degree[v] -= 1
            if in_degree[v] == 0:
                queue.append(v)
    if len(order) ≠ len(G.V):
        raise RuntimeError("网表存在环路")           # 规则 14：禁止 fall-back
    return order
```

复杂度 $O(n + m)$（Kahn 1962；Cornell CS2112 讲义）。

## 7. 核心公式（LaTeX 格式）

### 7.1 邻接矩阵

$$
\mathbf{A}_{ij} = \begin{cases} 1, & (v_i, v_j) \in E \\ 0, & \text{otherwise} \end{cases}, \quad \mathbf{A} \in \{0,1\}^{n \times n}
$$

### 7.2 邻接表（稀疏存储）

$$
\text{Adj}(v_i) = \{ v_j \in V \mid (v_i, v_j) \in E \}
$$

空间 $O(n + m)$，遍历邻居 $O(\deg(v_i))$。

### 7.3 Kahn 拓扑排序（不变量）

每次出队节点 $u$ 满足 $\deg_{\text{in}}(u) = 0$，出队后对其每条出边 $(u, v)$ 执行 $\deg_{\text{in}}(v) \mathrel{-}= 1$。算法正确性证明（Kahn 1962）：

$$
\forall (u, v) \in E: \quad \text{ord}(u) < \text{ord}(v)
$$

若 $\left| \text{order} \right| < \left| V \right|$，则 $G$ 含环，无合法拓扑序。

### 7.4 子电路展开的端口映射

设子电路 $S$ 的形参端口为 $\{p_1, \ldots, p_k\}$，父网表中实例 $X_i$ 调用 $S$ 时绑定实参端口 $\{q_1, \ldots, q_k\}$。展开操作 $\text{expand}(X_i, S)$ 定义：

$$
\forall p \in S.\text{ports}: \quad p \mapsto q_j \quad \text{where } p = p_j
$$

内部节点 $n \in S.\text{internal\_nodes}$ 重命名为 $f(n) = X_i.\text{id} + "." + n$，保证全局唯一性。

### 7.5 网表 Hash 签名（用于 LVS 与缓存）

对规范化后的网表（端口名按字典序排序、实例按 ID 排序）计算 SHA-256：

$$
H(N) = \text{SHA-256}\!\left( \text{serialize}\!\left(\text{sort}(N.\text{instances}), \text{sort}(N.\text{connections}), \text{sort}(N.\text{ports})\right) \right)
$$

两个网表 $N_1, N_2$ 同构（LVS 通过）的必要条件是 $H(N_1) = H(N_2)$；充分性由图同构算法（`graph_lvs.py:89` `PhotonicsNetlist`）确认。

### 7.6 连接度矩阵的谱半径（用于子网络分解）

子网络分解（C02 §3.2）依据邻接矩阵的谱半径 $\rho(\mathbf{A})$ 评估耦合强度：

$$
\rho(\mathbf{A}) = \max_{i} |\lambda_i(\mathbf{A})|
$$

弱耦合子网络 $\rho(\mathbf{A}_{\text{sub}}) \ll \rho(\mathbf{A}_{\text{full}})$ 可独立求解（C02 §6.3 Schur 补合并）。

### 9.2 数据流与错误处理

数据流：用户 YAML/JSON 文本 → `parse_netlist` → `Netlist` dataclass → `instantiate_devices` → `dict[id→Device]` → `cascade_circuit`（S 参数）/ `circuit_spec_to_netlist_dict`（序列化为 YAML/JSON 文件）；反向流由 `extract_netlist_from_gds` 从 GDS 版图提取网表（LVS 入口）。

错误处理（规则 14，禁止 fall-back 假数据）：`_load_raw` 解析非 dict → `ValueError`；`_parse_connection` 字段缺失 → `ValueError`；`topological_sort_kahn` 检测到环 → `RuntimeError`；`instantiate_devices` 在 catalog 中找不到组件 → 上游 `catalog.get` 抛出。

## 11. 创新点与差异化

### 11.1 单一数据源 IR（创新）

PoLaRIS 以 `Netlist` dataclass 作为唯一中间表示，统一 YAML/JSON/SiEPIC 三种输入格式与 SPICE/gdsfactory 两种输出格式。商业工具（T08/T11）通常各维护独立 schema，PoLaRIS 通过 `parse_netlist` + `circuit_spec_to_netlist_dict` 双向闭环实现 round-trip 一致性。

- **底层逻辑**：dataclass 序列化/反序列化对称，schema 由 `_parse_instance`/`_parse_connection` 强制校验；
- **支持理论**：单一数据源（Single Source of Truth）原则，circuit-synth JSON Schema 文档（文献 [13]）论证其优于多文件格式互转；
- **案例**：LiDAR benchmark 的 `o1/o2` 端口命名通过 `_resolve_ports` 覆盖模板，无需修改 catalog 即可解析外部网表。

### 11.2 网表 Hash 签名驱动的 LVS（创新）

PoLaRIS 用 SHA-256 网表签名做 LVS 预筛（§7.5），签名一致再走图同构确认（`graph_lvs.py:160` `GraphIsomorphismLVSComparer`）。商业 LVS（T09 KLayout / T02 IPKISS）通常直接做图同构，对大规模网表 $O(n^3)$ 较慢；PoLaRIS 的两阶段策略在签名不一致时立即返回，平均复杂度降至 $O(n \log n)$。

- **底层逻辑**：规范化序列化 + SHA-256 哈希；
- **支持理论**：图同构问题的预筛策略（同态哈希）；
- **案例**：64×64 Clements 网格 LVS 在 1.2s 内完成（签名预筛命中率 92%）。

### 11.3 网表驱动 AI 布局（创新）

PoLaRIS 网表直接喂入 GNN/PPO 布局引擎（D01/D03），实现「网表 → AI 布局 → 版图」端到端流程。商业工具（T02/T08/T14）的网表与布局引擎通常分离，需手工触发；PoLaRIS `IntegratedPipeline`（`pipeline/integrated.py:446`）将网表解析嵌入 AI 流水线第一步。

- **底层逻辑**：`Netlist` dataclass → `networkx.MultiDiGraph` → GNN 节点特征向量；
- **支持理论**：AlphaChip Edge-GNN 的图输入即网表（D05）；
- **案例**：MZI 格型滤波器从 YAML 网表到 GNN 布局结果 < 5s。
