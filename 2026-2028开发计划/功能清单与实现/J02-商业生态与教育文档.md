## 2. 物理模型与数学基础（知识工程、本体建模）

J02 聚类的"物理模型"并非电磁场方程，而是**光电子知识工程的本体建模**（Ontology Modeling）。PoLaRIS 采用"概念—属性—关系—实例"四级本体，对齐 Luceda Academy 的"Get Started → Learn → Examples → Reference"四层知识结构与 gdsfactory 的"Component/Netlist/Markdown Notebook"文档体系。

知识图谱建模为带类型的有向图 $G_K = (V_K, E_K, \tau_K)$：

- 顶点集 $V_K = \{\text{Concept},\ \text{Property},\ \text{Relation},\ \text{Instance}\}$，类型标签 $\tau_K(v) \in \Sigma_K$（如 `Waveguide`、`MZI`、`RingResonator`）。
- 边集 $E_K$ 编码四类关系：`is-a`（继承）、`has-property`（属性）、`connects-to`（电路连接）、`derives-from`（公式派生）。
- 每个顶点携带文档元数据 $M(v) = \{\text{title},\ \text{summary},\ \text{tags},\ \text{reference},\ \text{difficulty}\}$，用于检索与导航。

本体语义对齐 W3C OWL 2 与 schema.org 技术文档规范，保证 Luceda Academy Application Examples 与 gdsfactory notebooks 的概念可被同一知识图谱索引。这是 Luceda IPKISS PDK 多视图（Layout/Netlist/CircuitModel）与 simphony 文档 API Reference 在"概念—实例—引用"层统一的共同数学基础。

## 3. 控制方程（教学评估模型、内容生成）

教学评估满足**项目反应理论（Item Response Theory, IRT）三参数逻辑斯蒂模型**。设学习者能力为 $\theta \in \mathbb{R}$，教程项目 $i$ 的难度 $b_i$、区分度 $a_i$、猜测系数 $c_i$，则学习者答对概率：

$$P_i(\theta) = c_i + \frac{1 - c_i}{1 + \exp\!\big[-a_i(\theta - b_i)\big]} \tag{IRT}$$

教程内容生成采用**信息检索最大边际相关性（MMR）**。给定用户查询 $q$、候选文档集 $\mathcal{D} = \{d_1, \dots, d_N\}$，已选集合 $S$，迭代选取使下式最大的文档：

$$d^* = \arg\max_{d_i \in \mathcal{D} \setminus S}\ \big[\lambda\cdot \text{sim}(q, d_i) - (1-\lambda)\cdot \max_{d_j \in S}\text{sim}(d_i, d_j)\big] \tag{MMR}$$

其中 $\lambda \in [0,1]$ 权衡查询相关性与去冗余，$\text{sim}(\cdot,\cdot)$ 为余弦相似度。当 $\lambda = 1$ 退化为纯相关性检索，$\lambda = 0$ 退化为最大多样性。PoLaRIS 取 $\lambda = 0.7$，与 Luceda Academy "Get Started → Application Examples → Sample Gallery"三段式内容编排的"先相关后拓展"策略一致。所有评估与生成失败路径 fail-fast，禁止返回假教程或假评估分数（规则 14）。

## 4. 离散化方法（文档元数据、Sphinx 生成）

文档元数据"离散化"指将连续的教学内容（理论、公式、代码、案例）切分为可检索、可重用、可交叉引用的离散单元。两层处理：

**元数据 schema（Pydantic/dataclass）**：每个文档单元建模为带约束的类型 $T_d$，字段包括 `title:str`、`tags:set[str]`、`difficulty:Literal["beginner","intermediate","advanced"]`、`prereq:list[str]`、`estimated_minutes:int>0`、`source_url:HttpUrl`。校验即判定 $d \in \bigcap_{r \in \mathcal{K}} r(T_d)$，约束不满足时抛 `ValidationError`，不静默截断（规则 14）。

**Sphinx 生成（reST → HTML/PDF）**：源文档 $\to$ reST 树 $\to$ HTML 节点 的编译。设源文档 $S$ 经解析器 $\text{parse}: \mathcal{S} \to \mathcal{T}_{reST}$ 编译为 reST 抽象语法树，构建器 $\text{build}: \mathcal{T}_{reST} \to \mathcal{H}$ 输出 HTML。`toctree` 指令将多文件层次化连接为单一文档树，等价于给 reST 树加父子边 $(parent, child) \in E_{toc}$。Sphinx 5+ 默认支持 Markdown（via MyST-Parser）与交叉引用（`:ref:` 角色），保证 PoLaRIS 文档与 Luceda Academy、gdsfactory docs、simphony RTD 的浏览体验一致。

## 5. 边界条件（教学场景、用户分层）

教育文档的边界条件对应"用户边界 + 内容边界 + 许可边界"三类：

**用户边界（分层）**：依据 IRT 能力估计 $\hat{\theta}$ 将用户分为三档——`beginner`（$\hat{\theta} < -1$）、`intermediate`（$-1 \le \hat{\theta} \le 1$）、`advanced`（$\hat{\theta} > 1$）。教程推荐按档位过滤，跨档访问给出前置教程提示而非直接拒绝。这与 Luceda Academy "Get Started → Learn IPKISS → Application Examples"分层、Ansys Innovation Space "Free Courses 1-6 HOURS"难度标注、MIT edX PIC1 "8 weeks, 15-20 hours/week, Advanced"分级同构。

**内容边界（覆盖度）**：教程案例库覆盖度 $C = |\text{tutorials} \cap \text{features}| / |\text{features}|$。当前 PoLaRIS 案例库覆盖 11/22 = 50%（T15 应用案例对齐部分）；未覆盖案例返回 `TutorialNotFoundError`，禁止用通用文档冒充专用教程（规则 14）。

**许可边界（开源 vs 商业）**：商业培训（Luceda Academy 账号申请、SimWorks 设计服务、曼光专利布局）属 🚫战略剔除项，PoLaRIS 以 CC-BY-4.0/Sphinx 开源文档替代，不伪造商业服务入口。开源贡献遵循 `CONTRIBUTING.md` + CITATION.cff（T11 simphony 标准）。

def build_docs(source_dir, builder="html"):

def recommend_tutorials(user, query, k=5):

### 6.3 案例匹配（知识图谱节点中心性 + TF-IDF）

```python
def match_case(user_query, case_graph):
    q_vec = tfidf_vectorize(user_query)                  # 公式 (2)
    scores = {c: cosine(q_vec, tfidf_vectorize(c.doc)) for c in case_graph.cases}
    centrality = pagerank(case_graph)                    # 公式 (4)
    final = {c: alpha * scores[c] + (1-alpha) * centrality[c] for c in scores}
    return sorted(final, key=final.get, reverse=True)[:5]
```

## 7. 核心公式

### (1) 知识图谱节点介数中心性（Betweenness Centrality）

教程"前置—后续"依赖图中，节点 $v$ 的介数中心性衡量其作为知识桥梁的重要度。设 $\sigma_{st}$ 为从 $s$ 到 $t$ 的最短路径数，$\sigma_{st}(v)$ 为经过 $v$ 的最短路径数：

$$C_B(v) = \sum_{s \neq v \neq t \in V} \frac{\sigma_{st}(v)}{\sigma_{st}} \tag{1}$$

归一化后 $C_B^*(v) = C_B(v) / \big[(|V|-1)(|V|-2)/2\big] \in [0,1]$。Brandes 算法以 $O(|V||E|)$（无权图）或 $O(|V||E| + |V|^2 \log|V|)$（有权图）一次遍历计算所有节点介数。PoLaRIS 用 `networkx.betweenness_centrality` 实现，识别"波导→MZI→Add-Drop"等核心枢纽教程，优先补齐（对应功能点 9/10）。

### (2) TF-IDF 文档检索

教程库 $\mathcal{D}$ 含 $N$ 篇文档，词项 $t$ 在文档 $d$ 中出现 $f_{t,d}$ 次，文档长度 $|d|$。TF-IDF 权重：

$$\text{tfidf}(t, d) = \frac{f_{t,d}}{|d|} \cdot \log\frac{N + 1}{\,|\{d' \in \mathcal{D} : t \in d'\}| + 1\,} + 1 \tag{2}$$

文档向量 $\mathbf{v}_d = (\text{tfidf}(t_1,d), \dots, \text{tfidf}(t_V,d))$，查询 $\mathbf{v}_q$ 同法构造，余弦相似度 $\text{sim}(q,d) = \mathbf{v}_q \cdot \mathbf{v}_d / (\|\mathbf{v}_q\|\|\mathbf{v}_d\|)$。PoLaRIS 用 `sklearn.feature_extraction.text.TfidfVectorizer` 实现，对齐 Sphinx 全文搜索与 Luceda Academy 关键词检索。

### (3) 学习路径推荐（前序约束 + 难度递增）

设教程依赖图 $G_T = (V_T, E_T)$，前序约束 $(u,v) \in E_T$ 表示 $u$ 必须先于 $v$ 学习。学习路径 $P = (v_1, v_2, \dots, v_k)$ 为 $G_T$ 的拓扑路径，目标函数：

$$\max_{P}\ \sum_{i=1}^{k} w(v_i)\cdot \mathbb{1}[\text{rel}(v_i, q)] - \mu\sum_{i=1}^{k-1}|b_{v_{i+1}} - b_{v_i}| \tag{3}$$

约束：$P$ 为 $G_T$ 上的合法拓扑序（前序必先出现），难度 $b_{v_i}$ 单调不减，长度 $k \le K_{\max}$。$w(v_i)$ 为节点权重（可取介数中心性 $C_B^*(v_i)$），$\mu$ 为难度跳变惩罚系数。该问题为带约束的最长路径变式，PoLaRIS 用动态规划 $O(|V_T|+|E_T|)$ 求解（DAG），与 Luceda Academy "Get Started → Learn → Examples"递进式路径同构。

### (4) PageRank 教学资源排序

教程案例图 $G_C = (V_C, E_C)$，节点为案例，边为"引用/相关"关系。PageRank 迭代：

$$PR(v) = \frac{1-d}{|V_C|} + d \sum_{u \in \text{In}(v)} \frac{PR(u)}{\text{Out}(u)} \tag{4}$$

阻尼系数 $d = 0.85$，迭代至 $\|PR^{(t+1)} - PR^{(t)}\|_1 < 10^{-6}$ 收敛，复杂度 $O(|E_C|)$ 每次迭代。PoLaRIS 用 `networkx.pagerank` 实现，将 PageRank 与 TF-IDF 加权融合（公式 §6.3），抑制低质量案例排名靠前。

### (5) 教学评估混淆矩阵与 F1

教程学习后测验的混淆矩阵 $M \in \mathbb{Z}^{K \times K}$，$M_{ij}$ 为真实知识点 $i$、预测知识点 $j$ 的样本数。多类 precision/recall/F1：

$$P_j = \frac{M_{jj}}{\sum_i M_{ij}},\quad R_j = \frac{M_{jj}}{\sum_i M_{ji}},\quad F1 = \frac{2\sum_j M_{jj}}{2\sum_j M_{jj} + \sum_{i \neq j} M_{ij} + \sum_{i \neq j} M_{ji}} \tag{5}$$

macro-F1 为各类 F1 算术平均。PoLaRIS 用 `sklearn.metrics.classification_report` 输出，对齐 MIT edX PIC1 课程评估与 Ansys Innovation Space 完成徽章（Completion Badge）机制。评估结果以结构化 JSON 上报，失败路径 fail-fast（规则 14）。

## 11. 创新点与差异化

*创新* 以下为 PoLaRIS 在 J02 聚类的差异化设计，均标注创新逻辑与支持理论：

1. **知识图谱统一教程/案例/文档索引**：将 Luceda Academy "Get Started/Learn/Examples/Reference"、gdsfactory notebooks、simphony RTD、T15 应用案例统一为本体图 $G_K$，TF-IDF + PageRank + 介数中心性三公式联合检索。底层逻辑：知识工程 + 图论；支持理论：W3C OWL 2 本体、Brandes 2001 介数算法、PageBrin 1998 PageRank；案例：Luceda Academy 已验证"概念—实例—引用"分层可行，PoLaRIS 进一步统一为单图多源索引，减少跨平台格式转换开销。
2. **IRT 三参数能力估计 + MMR 个性化教程推荐**：公式 (IRT)(MMR)(3) 联合实现按能力分层的非冗余教程路径。底层逻辑：教育测量学 + 信息检索；支持理论：Lord 1980 Item Response Theory、Carbonell-Goldstein 1998 MMR；案例：Ansys Innovation Space 难度标注 + MIT edX PIC1 Advanced 级别已验证分层可行，PoLaRIS 进一步以 IRT 数值化 $\hat{\theta}$ 替代主观分级。
3. **fail-fast 教程缺失告警**：教程不存在、跨档访问、交叉引用断链均立即抛错，不返回通用文档冒充专用教程。底层逻辑：Hoare 契约 + PEP 20；支持理论：规则 14 禁止 fall-back，Sphinx broken xref warning、Luceda Academy 404 页均属快速失败范式。
4. **Sphinx + MyST-Markdown 开源文档流水线**：与 simphony RTD 共享 Sphinx + ReadTheDocs 托管，但增加 MyST-Parser 支持 Markdown 源（Luceda Academy 专有 reST）。底层逻辑：单源多输出（HTML/PDF/ePub）；支持理论：Sphinx 文档证明 reST/Markdown 混合可行，gdsfactory notebooks 已验证 Markdown + 代码块 + 交叉引用可用。
5. **开源战略剔除商业服务/专利**：明确将 T15 知识产权专利（8 项 🚫）、T16 设计服务（2 项 🚫）、T02 IP Manager/Academy（商业培训）标为战略剔除，不伪造入口。底层逻辑：开源商业模式与商业 EDA 边界明晰；支持理论：MIT/Apache 协议生态（simphony/gdsfactory/sax）已证明开源可绕过商业专利壁垒，CC-BY-4.0 文档许可替代商业培训订阅。
